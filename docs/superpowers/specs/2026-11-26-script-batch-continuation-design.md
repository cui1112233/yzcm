# 分批剧本生成与续接

本设计落实总计划 D10 的第一部分：专业剧本2（293）在章节生成入口按原件的 batch_info / unprocessed_script_rollover 合同保存、继续和完成。138 另做独立分镜合同，不借本改动直接开放。

## 用户看到的行为

- 一次点击只调用一次模型。部分结果显示“本批已保存，待继续”，旧成功剧本保留；用户点击“继续生成剩余剧本”才处理剩余原文。
- 当前任务完整结束，才把各批合法场景合并成新剧本版本，原始回包逐批留存。不能把未完成结果当作完整合集交给后续生产。
- 页面刷新后仍能看到批次与继续入口。修改原文、提示词、模型或相关生成配置后，旧续接不能继续，必须明确重新开始。
- 失败、取消、超时保留已有批次。请求已发出但结果不确定时不自动重发；明确重试可能再次扣费。

## 保存与约束

- 沿用 AuthoringRepository 的持久化与版本检查，章节增加独立 script_generation 状态；不可从前端提交伪造的运行状态，普通章节编辑应保留服务器状态并使变更后的任务失效。
- 保存来源摘要、提示词及正文摘要、模型/配置摘要、每批输入摘要、原始回包、状态和剩余原文。开始请求先落运行状态，返回结果再落状态；失败用独立短时上下文记录，不能因HTTP取消而抹去已返回内容。
- 同章节在运行中、未知结果、已完成时不得因重复点击再次付费；继续操作只消费待续接状态。原文/配置变动拒绝续接。
- 逐批 JSON 严格检查：is_complete 必须是布尔值，current_batch 连续，场景和元素编号无跨批重复，剧集一致；非完成批次的 rollover 必须是当前输入逐字后缀、非空、严格缩短，并从完整句子边界开始；完成批次 rollover 必须为空。
- 有效批次才进入合并正文，非法回包保留诊断，不能覆盖旧成功结果。设置批次、字节和场景数量上限。
- 合并后的 RawResult 保留完整 scenes 结构，保持来源覆盖检查可用；批次原始响应单独留存。
- 全局开放293前要覆盖所有能够选择该模板的入口。尚无续接能力的单次A1/B入口必须在请求模型前明确拒绝293，不能静默保存半成品。旧144、139与自定义模板不回退。

## 验收

先写失败用例，再实现：两批完成、刷新续接、原文失配、非后缀/未进展、缺布尔字段、批次错序、跨批重复、取消/失败保留、重复提交、跨用户、普通编辑不能伪造生成状态。真实组件验证状态与继续动作。使用受控模型回包验证，不进行真实付费生成。
