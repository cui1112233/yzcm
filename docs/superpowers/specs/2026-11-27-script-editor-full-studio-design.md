# 剧本编辑完整短剧工作室复刻设计

日期：2026-11-27  
目标入口：`/script-editor`  
用户可见名称：`剧本编辑`  
参考产品：洛水 2026“短剧工作室（作品库）”及其作品详情、Agent、资产、分镜和画布联动

## 1. 目标

“剧本编辑”不是一个只负责写文字的轻量编辑器，而是洛水“短剧工作室”的完整复刻版。除用户可见名称改成“剧本编辑”外，作品库、作品详情、AI 创作、资产、分镜、画布、生产、后期和交付链路都要完整进入同一个工作室。

完整闭环为：

`创建或导入作品 → 整理小说 → 多版本剧本 → Agent 协作 → 资产分析与设计 → 分镜规划和编辑 → CM 画布 → 图片/视频/配音生产 → 后期 → 导出交付`

洛水的 momo 画布对应 V88 已有的 CM 画布。CM 画布继续使用现有真实节点、连线、素材、模型任务和持久化能力，但从“剧本编辑”当前作品进入时必须自动加载同一作品上下文，不能只放一个无上下文跳转链接。

## 2. 复刻原则

### 2.1 名称规则

- 洛水“短剧工作室”在 V88 中统一显示为“剧本编辑”。
- 洛水“momo 画布”在 V88 中显示为“CM 画布”。
- 页面标题、按钮、空状态、任务状态和提示文案按洛水语义复刻；只有上述产品名称允许替换。
- 内部兼容路由、数据表和 Go 类型可以保留现有名字，不能为了改名破坏已有作品。

### 2.2 复用规则

- 不复制第二套 CM 画布、漫剧项目、AI-CUT、配音或生成队列。
- “剧本编辑”提供洛水式工作室外壳和流程，具体媒体能力调用 V88 已有 Go 服务。
- 复用不等于简单跳转。进入子工作区时必须携带当前作品、剧本、集数、资产和分镜身份；退出后回到原作品和原位置。
- 系统提示词全部保存在 Go 后端 `prompt` 模块，前端只提交提示词槽位和用户补充要求。

### 2.3 数据规则

- MySQL 是作品、章节、剧本版本、资产、分镜、任务和绑定关系的真相来源。
- Redis 只用于队列唤醒、分布式锁和临时运行信号，Redis 丢失不能造成作品或任务丢失。
- TOS 保存需要长期留存的图片、音频、视频和大文件；MySQL 保存元数据和引用。
- 所有 AI 或媒体任务都必须有状态、进度、失败原因、取消、重试和刷新恢复。
- 模型请求可能已经发出但结果未知时，不得自动重复扣费；必须显示“结果待确认”。

## 3. 产品信息结构

### 3.1 一级作品库

作品库复刻洛水 WorksLibrary，包含：

- 新建作品、导入小说、导入剧本。
- 宫格和列表两种视图。
- 搜索、作品类型、标记状态、创建/更新时间排序。
- 个人作品和团队作品入口；团队数据不可用时明确显示空状态，不伪造数据。
- 作品卡片封面、标题、类型、章节数、剧本版本数、人物/场景/道具数量、更新时间和任务状态。
- 右键或“更多”菜单：打开、重命名、复制、导出、打开关联工作区、标记、软删除。
- 挂机任务入口和任务面板：待执行、倒计时、执行中、暂停、失败、完成。
- 删除采用二次确认和软删除；已有作品不可因升级或筛选丢失。

### 3.2 作品详情总布局

作品详情使用洛水三栏结构：

- 左侧窄 rail：返回、小说、剧本、资产、分镜、CM 画布、生产、交付、设置。
- 中间 aside：当前标签对应的章节、版本、资产分类、集数或任务列表。
- 主区：编辑器、对照区、资产工作台、分镜工作台、任务详情或交付结果。
- Agent 可停靠在右侧，也可切换为悬浮窗口；切换标签不丢会话。
- 顶部显示作品名称、作品类型、章节/剧本/人物/场景/道具/分镜统计和当前保存状态。
- 布局比例、侧栏开关、字号、主题和上次打开位置按账号保存。

## 4. 小说与文稿功能

### 4.1 章节管理

- 自动识别 TXT、Markdown、DOCX 中的章节。
- 导入前预览，用户确认后才创建或追加内容。
- 章节新增、重命名、自动保存、删除、复制、上移下移和拖动排序。
- 全文搜索覆盖章节标题和正文，结果显示命中位置并可跳转。
- 显示字数、更新时间和是否已被剧本引用。
- 支持“追加导入”“替换当前章节”“导入为新作品”，任何覆盖操作必须二次确认。

### 4.2 原文与剧本对照

- 剧本页默认显示原文对照栏和当前剧本栏。
- 对照栏可按剧本绑定的一个或多个原文章节组合展示。
- 点击原文锚点可跳到剧本对应段落；点击剧本来源标记可回到原文。
- 对照栏和分镜栏可以独立开关，栏宽自动保存。

## 5. 剧本与版本功能

### 5.1 分集和多版本

- 新建单集、新建多集、导入单个剧本、批量导入多版本剧本。
- 按集排列，同集版本相邻；显示版本号、正式版、来源、模型、字数、更新时间和分镜状态。
- 支持复制为新版本、重命名、删除、查找替换和自动保存冲突处理。
- 支持多个版本并排比较、差异高亮、选择片段合并和将某一版设为正式版。
- 每集只能有一个正式版；未选择正式版的集不能进入最终交付。
- 导入不会覆盖同集旧版本，而是创建新版本。

### 5.2 AI 剧本能力

- 小说转分集剧本，可选择章节范围、目标集数、每集章数、版本数、并发数、模型、核心提示词、文风和额外要求。
- 支持 AI 审稿、剧本优化、爆款开头、台词差异、两个版本融合和继续追问。
- AI 结果先进入候选结果区；用户明确采用后才创建新版本。
- 批量任务逐集保存，局部成功不能因其他集失败而回滚。
- 失败重试只重跑失败集；成功集和用户手工修改内容保持不变。

### 5.3 剧本编辑器

- 识别集标题、场次、人物、地点、时间、动作、台词和备注。
- 支持字号、标记高亮、居中阅读、行号和来源锚点。
- 查找替换支持当前版本、当前集全部版本和全部剧本三种范围。
- 保存冲突时保留本地内容，显示服务端版本差异，由用户选择重新载入、复制为新版本或合并。

## 6. Agent 工作区

- 每个作品有独立 Agent 会话列表、消息历史、文件面板和子会话。
- 支持 `@` 引用章节、剧本、资产、分镜和任务，支持 `/` 选择 Skill。
- 权限模式包括：直接写入、写入前确认、只读分析、询问。
- Agent 可创建或修改章节、剧本版本、资产草案和分镜草案；所有写操作产生可审计记录。
- 支持取消当前回复、继续运行、失败重试和恢复中断会话。
- 支持工作流编排、并行子任务和阶段进度；不得只显示一段无法追踪的聊天文本。

## 7. 资产功能

### 7.1 资产分类与分析

- 人物、场景、道具和导演台四类工作区。
- 支持按名称、标签、主角、Q 版、群像、衍生和其他分类筛选。
- 可从小说、剧本或指定集分析资产，支持覆盖或追加模式。
- 资产分析范围可选择人物、场景、道具或全部，结果先预览再保存。

### 7.2 资产编辑与生成

- 人物包含名称、别名、外观、服装、性格、关系、声音和参考图。
- 场景包含名称、时间、环境、布局、气氛和参考图。
- 道具包含名称、外观、用途、归属角色和参考图。
- 支持上传、从“我的资产”选择、AI 生成、局部重绘、历史结果、设为主图和删除。
- 支持模型、尺寸、画风、参考图和额外要求配置。
- 支持将作品资产同步到 CM 画布和漫剧创作，绑定使用稳定资产 ID，不靠名称猜测。

## 8. 分镜功能

### 8.1 分镜规划

- 按正式剧本或指定版本生成分镜规划。
- 支持规划密度、目标时长、镜头节奏、画风、模型、上下文历史和额外要求。
- 分镜规划可保存、删除、重新生成、继续生成和手工编辑。
- 显示剧本覆盖率，明确列出未覆盖段落和重复覆盖段落。

### 8.2 分镜编辑

- 按集、场景和镜头组织；支持新增、复制、删除、拖动排序和批量操作。
- 每个镜头包含画面、景别、机位、运镜、人物、场景、道具、台词、旁白、时长、图片提示词、视频提示词和负面提示词。
- 支持 JSON 和可读文本两种视图，格式错误时不覆盖上一次有效内容。
- 支持 Agent 追问、AI 修复、拆分、合并、补镜和覆盖率检查。
- 支持站位参考、角色/场景/道具绑定和上一镜尾帧引用。

## 9. CM 画布（洛水 momo 画布映射）

### 9.1 进入方式

- 作品 rail 中的“CM 画布”直接打开当前作品绑定的画布。
- 第一次进入自动创建画布任务并写入 `script_editor_work ↔ agent_task` 绑定。
- 已绑定时恢复节点、连线、视口、选中项、历史结果和草稿。
- 独立左侧“CM 画布”入口继续可用；从独立入口打开同一画布时看到同一数据。

### 9.2 同步内容

- 可将章节、正式剧本、指定剧本版本、资产和分镜同步成画布节点。
- 每个同步节点保存稳定来源 ID、来源版本和最后同步时间。
- 同步前显示新增、更新、冲突和不变数量。
- 用户在画布中手工修改的节点不能被后台刷新静默覆盖；冲突必须选择保留画布、采用作品或复制节点。
- 从画布生成的文字、图片、视频和音频可回写作品资产或指定镜头，回写前显示目标。

### 9.3 画布能力

- 保留现有 CM 画布的节点、连线、分组、拖拽、缩放、小地图、自动布局、撤销重做和自动保存。
- 支持文本、剧本、分镜、人物、场景、道具、图片、视频、音频和导演台节点。
- 连线代表引用关系，生成请求必须读取上游节点和绑定资产。
- 支持模型选择、参考素材、尺寸/比例、生成候选、确认采用、取消、失败重试和历史结果。
- 支持画布 Agent、素材库、文件视图和导演台，不创建第二套简化画布。

## 10. 图片、视频、配音与生产

- 图片生成复用现有统一模型目录、参考图合同、候选确认和结果资产保存。
- 视频生成复用现有视频任务、首尾帧、参考图、时长、比例、模型、取消、重试和回读机制。
- 配音支持角色音色、旁白、试听、重新生成、波形、时间对齐和镜头绑定。
- 支持字幕生成、字幕校正、粗剪、片段重拍、超长视频、连续播放和白模视频。
- 批量生产逐镜头保存结果，任务页面显示排队、生成、下载、保存和失败阶段。
- 任何可能扣费的生成都由用户明确提交；自动重试遵守已有扣费保护边界。

## 11. 后期与交付

- 导出当前选择、每集正式版或勾选集数。
- 支持合并 TXT、逐集 ZIP、结构化 JSON、素材清单和项目归档。
- 支持导入漫剧创作，并保持集数、顺序、正文、资产和分镜绑定。
- 支持进入 AI-CUT 继续剪辑，并携带当前项目和媒体引用。
- 剪映草稿导出复用现有后端能力；缺少本地依赖时明确提示，不生成假成功文件。
- 交接使用幂等 request key；重复点击不能创建重复项目。

## 12. 设置

- 作品级设置：默认模型、提示词、剧本风格、画风、比例、任务并发、自动保存和分镜密度。
- 账号级模型仍由统一 API 配置管理；作品只保存模型 ID，不复制密钥。
- 设置修改影响后续任务，不追溯改写已经完成的历史结果。
- 设置窗口显示继承来源：系统默认、账号默认或作品覆盖。

## 13. 统一数据绑定

新增独立绑定表，不把多个模块的数据硬塞进一个 JSON：

- `script_editor_work_bindings`：作品与漫剧项目、CM 画布任务、AI-CUT 项目的稳定绑定。
- `script_editor_source_links`：章节、剧本版本、分镜和画布节点之间的来源关系。
- `script_editor_asset_links`：作品资产与画布资产、漫剧资产之间的关系。
- `script_editor_job_links`：作品任务与下游生成任务的关系。

绑定表都包含账号、作品 ID、目标类型、目标 ID、来源版本、同步状态、冲突状态、创建时间和更新时间。删除作品采用软删除，不级联删除下游项目或媒体。

## 14. 错误和恢复

- 刷新、退出重进、服务重启后，作品位置、草稿和任务状态可恢复。
- MySQL 写入失败时前端不显示成功；媒体上传成功但绑定失败时保留媒体并显示“待绑定”。
- 下游 CM 画布、漫剧创作或 AI-CUT 不可用时，当前作品仍可编辑，并显示具体不可用模块。
- 任务取消必须区分“尚未发送”“请求可能已发送”“结果已保存”。
- 导入、同步、采用结果和交接均使用幂等键。
- 409 冲突不能自动覆盖，必须保留用户本地内容并提供明确处理入口。

## 15. 实施拆分

完整工作室跨越多个独立子系统，按五个可单独验收的阶段实施：

1. **作品库和完整编辑能力**：补齐标记、删除、搜索、导入剧本、原文对照、多版本并排和勾选导出。
2. **Agent、资产和分镜**：接入作品 Agent、资产分析/编辑、分镜规划/编辑和覆盖率。
3. **CM 画布绑定**：实现作品与现有 CM 画布的稳定绑定、同步预览、冲突处理和双向回写。
4. **媒体生产和后期**：把现有图片、视频、配音、字幕、AI-CUT 和剪映能力放入工作室流程。
5. **洛水级页面和状态验收**：逐页核对空状态、有数据状态、弹窗、任务恢复、交互和视觉。

每个阶段都必须先在本机 4001 构建和验收；前一阶段未通过时不把后一阶段称为完成。

## 16. 验收标准

### 16.1 功能

- 洛水作品库和作品详情中用户可操作的功能都有对应真实实现，不存在只有按钮无行为的占位。
- momo 画布能力由 CM 画布承接，作品和画布之间可双向同步且能处理冲突。
- 作品可以从导入原文一直走到分镜、媒体生产和交付，不需要手工复制 ID 或正文。

### 16.2 数据

- 同一账号只能访问自己的作品、绑定、资产和任务。
- 刷新、重启和切换模块后数据一致。
- 重复提交不产生重复作品、版本、画布、漫剧项目或付费任务。
- 旧“剧本编辑”测试作品和已有 CM 画布保持可用。

### 16.3 页面

- 分别验证作品库、小说、剧本、Agent、资产、分镜、CM 画布、生产、交付和设置。
- 每个页面分别验证空状态、有数据状态、加载状态、失败状态和无权限状态。
- 页面结构、主要尺寸、层级、颜色、按钮位置和弹窗按洛水参考资料核对，不用粗糙占位界面代替。

### 16.4 运行

- React 测试和正式构建通过。
- Go 领域、存储、HTTP、任务和绑定测试通过。
- Go embed 二进制在本机 4001 启动，`/health` 和 `/api/runtime-build-info` 与构建提交一致。
- 真实浏览器完成不扣费链路；付费模型和媒体调用只有获得明确授权后才执行。
- 不发布公网，不使用 GitHub Actions 部署。
