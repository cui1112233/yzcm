# 个人中心、能量体系与四级账号权限设计

日期：2026-11-26
状态：设计已通过口头评审，等待书面复核；尚未实施。
维护主线：`v88`。本设计只描述产品与技术边界，不代表功能已经上线。

## 1. 设计目标

重新整理一战晟铭个人中心，删除虚假的会员包装和重复页面，把真实可用的账号、能量、团队、模型配置与安全能力集中起来。

核心目标：

1. “能量”是 YZCM API 实际余额在一战晟铭中的展示名称，`1 能量 = 1 元 YZCM 可用额度`，不建立第二套钱包，也不重复扣款。
2. 所有身份都能看到所属团队的剩余能量和成员消耗；开发创始与开发者能查看所有团队的消费与各团队余额。
3. 个人资料不再与会员中心重复，原会员中心及虚假会员权益退出主导航。
4. 四种正式身份统一为：`开发创始`、`开发者`、`管理者`、`组员`。
5. API 配置沿用当前真实功能和操作方式，仅按身份隐藏能力，并把管理者的模型来源收口到 YZCM API。
6. 全站使用已有的动态能量背景和通透玻璃视觉，身份图标小型化并放在名字旁边。

## 2. 与既有设计的关系

本设计延续 `2026-11-25-yzcm-managed-models-team-accounts-design.md` 中已确认的 YZCM 模型目录、独立团队钱包、真实消费日志、自动开户和统一验证方向。

以下内容以本文为准：

- 旧“会员中心”不再作为独立产品中心；余额、用量和账单合并进“能量与账单”。
- 团队余额对所属团队的全部身份可见，不再由管理者单独决定是否展示。
- 身份体系改为本文的四级权限模型。
- 管理者的“自定义预设”只显示 YZCM 模型，不保留 DeepSeek、豆包、千问、OpenRouter 等外部预设。
- API 配置不新增团队默认 Key 面板，也不常驻展开模型选择器。

本文不改变 YZCM API 中转站本身，不新增支付通道，也不改变既有模型价格与实际扣费规则。

## 3. 信息架构

个人中心左侧导航按以下顺序组织：

1. 账户总览
2. 个人资料
3. 能量与账单
4. 账号安全
5. 团队管理
6. API 配置（组员不显示）
7. YZCM API（外部中转站入口）
8. 账号与角色（仅开发创始、获得授权的开发者显示）

左侧底部固定“返回工作台”和“退出登录”。顶部显示当前头像、用户名、紧邻用户名的小型身份图标、正式身份名称和“切换账号”入口；没有切换权限的身份不显示入口。

## 4. 四级身份与权限

### 4.1 正式身份

| 身份 | 定位 | 团队能力 | 平台能力 |
| --- | --- | --- | --- |
| 开发创始 | 唯一最高身份 | 可以拥有团队和组员，查看与管理全部团队 | 完整后台、账号、权限、开发配置、自定义模型和地址；任命或取消开发者 |
| 开发者 | 权限更高的管理者 | 可以新建团队，管理自己创建或被分配的团队；可查看所有团队余额和消费 | 由开发创始授权进入管理后台、账号和开发配置；可添加自定义模型和地址 |
| 管理者 | 团队负责人 | 管理本团队组员、模型 Key、团队使用情况 | 只能使用 YZCM 模型，不可自定义请求地址或新增自定义模型 |
| 组员 | 团队使用者 | 使用管理者配置的模型，查看团队剩余能量和团队消耗 | 不显示 API 配置，不可读取完整 Key |

“开发创始”是正式名称，不再使用“星核掌控者”等装饰性角色名。身份象征由图标承担，文字始终使用以上四个名称。

### 4.2 权限授予边界

- 只有开发创始可以任命、取消或调整开发者权限。
- 开发者可以创建管理者和组员，不能创建开发者，也不能修改开发创始。
- 管理者只能管理自己团队的组员，不能创建管理者或开发者。
- 组员没有账号管理权限。
- 前端隐藏不是安全边界；所有读取、修改、导出和切换操作必须由后端再次校验真实身份、授权范围和目标账号。

### 4.3 团队创建、停用与归档

- 开发创始和获得相应授权的开发者可以新建团队。
- 停用账号后禁止新登录与新业务请求，历史账单、作品归属和审计记录保留。
- 归档团队后禁止新请求，剩余能量冻结并保留在原团队；恢复团队后继续使用。
- 能量不自动转到其他团队。确需转移时由开发创始单独操作，并记录来源、目标、数量、原因和操作者。
- 永久删除只允许开发创始执行，必须二次确认；有余额、在途任务、未完成核账或法定留存数据时必须阻止删除。

## 5. 账号切换与排查

### 5.1 可切换范围

| 当前身份 | 可切换目标 |
| --- | --- |
| 开发创始 | 任意非自身账号，包括开发者、管理者和组员 |
| 开发者 | 各团队的管理者和组员，不可切换为开发创始 |
| 管理者 | 仅自己团队的组员 |
| 组员 | 不可切换 |

### 5.2 切换后的行为

- 允许执行普通业务操作，以便真实复现问题。
- 页面顶部持续显示醒目的“正在以某账号操作”状态条，并提供一键退出切换。
- 业务消耗、作品和任务归属目标账号；审计同时记录真实操作者和目标账号。
- 切换状态下禁止修改目标账号的密码、MFA、Passkey、身份、团队归属、团队所有权和完整 API Key。
- 需要执行以上敏感动作时，必须退出切换状态后从正式管理入口操作。
- 切换会话设置明确有效期，退出登录、主动退出切换或会话失效后立即结束。

## 6. 页面设计

### 6.1 账户总览

首页只展示真实可用信息：

- 所属团队及当前身份。
- 团队剩余能量和更新时间。
- 今日、本月和累计已核账消耗。
- 待核账请求数量，不把未知金额补成零。
- 团队成员能量消耗排行榜；明确排行时间范围。
- 最近安全活动与常用入口。
- “补充能量”跳转现有 YZCM API 中转站，不在个人中心重复实现充值。

开发创始和开发者增加“所有团队概览”：展示平台总消耗、各团队消耗和各团队剩余能量。可以汇总消费，但不同团队的钱包余额只能逐队列出，不生成虚假的合计余额。

### 6.2 个人资料

采用紧凑布局，不再使用占据大面积的身份卡：

- 顶部横向资料条包含头像、显示名称、账号、正式身份和小型身份图标。
- 主区域左侧编辑显示名称、手机号、邮箱和个人简介；右侧显示账号归属与资料可见范围。
- 登录账号、团队归属和系统身份由系统管理，个人资料页不可自行修改。
- 手机号和邮箱按权限脱敏；公开范围的修改必须有明确说明。

身份图标约 24–28 像素，紧邻用户名。四种图标使用同一品牌 Logo 的不同能量形态，不使用通用皇冠或盾牌替代品牌形象。

### 6.3 能量与账单

页面统一承接原会员中心和用量页的真实数据：

- 顶部：团队剩余能量、今日消耗、本月消耗、累计消耗、待核账数量和更新时间。
- 趋势：按日、周、月查看实际消耗。
- 排行：团队成员消耗排行，所有团队成员都可见；不得显示其他团队成员。
- 明细：时间、成员、项目、功能、模型、用量、实际扣费和核账状态。
- 筛选：时间、成员、项目、能力类型和核账状态；列表、汇总和导出必须使用同一筛选条件。
- 充值：只提供“前往 YZCM API 补充能量”和充值记录入口，不复制支付能力。

余额查询失败时显示“暂无法获取”和上次更新时间，不能显示为 0。制作成功与收费核账保持两个独立状态。

### 6.4 账号安全

保留并落实为真实能力：

- 修改自己的密码。
- TOTP MFA。
- Passkey / WebAuthn 安全密钥。
- 邮箱验证与恢复邮箱。
- 当前设备、其他登录设备和最近活动。
- 一键退出其他设备。
- 安全活动记录。
- 登录页“忘记账号”和“忘记密码”。

删除没有可靠依据的“安全分数”。设备列表必须补齐可获得的浏览器、操作系统、最近活动和模糊 IP；无法识别时明确显示未知，不虚构设备信息。

当前 MFA 密钥若仍以明文保存在本地 JSON 中，不得按生产可用验收；上线前必须迁移到受保护或加密存储。

恢复邮箱规则：一个账号只绑定一个已验证恢复邮箱，一个已验证邮箱只能绑定一个账号。

### 6.5 管理员重置密码

| 操作者 | 可重置范围 |
| --- | --- |
| 开发创始 | 开发者、管理者、组员；不能通过管理入口重置自己 |
| 获授权开发者 | 管理者和组员；不能重置开发创始 |
| 管理者 | 自己团队的组员 |
| 组员 | 只能自行改密或走邮箱找回 |

重置后系统生成一次性临时密码，撤销旧会话，并要求目标账号下次登录强制改密。目标账号有已验证邮箱时发送到邮箱；没有邮箱时只向管理员显示一次。全过程记录操作者、目标、时间和结果，审计中不得保存明文临时密码。

### 6.6 团队管理

管理者看到本团队；开发创始和开发者按权限查看多个团队。页面包含：

- 团队剩余能量、本月消耗、成员数和待处理事项。
- 成员列表与状态。
- 成员能量消耗排行。
- 邀请或新建组员、停用账号、重置密码。
- 管理者对本团队组员的账号切换入口。
- 最近团队操作与审计记录。

团队管理不显示完整模型 Key，也不允许通过切换账号绕过敏感操作限制。

### 6.7 API 配置

API 配置必须以本地 4001 当前真实页面为基础，保留平台预设模型、按能力折叠分组、Key 自动保存、额度刷新及其他真实配置分组，不另造一套“团队模型”页面。

#### 开发创始与开发者

- 保留当前完整配置能力。
- 可以使用“自定义预设”和“添加自定义模型”。
- 可以选择 API 格式、填写自定义请求地址、模型 ID、显示名称、Key 和高级配置。
- 开发者能否使用开发配置由开发创始授权；撤销授权后后端同时禁止相关接口。

#### 管理者

- 保留现有平台预设区、能力分组、Key 自动保存、额度刷新和相关附加配置。
- “自定义预设”只从后台已保存的 YZCM 允许目录读取模型，不保留 DeepSeek、豆包、千问、OpenRouter 等外部预设。
- 预设弹窗支持按名称或模型标识搜索；左侧勾选，右侧查看和移除已选模型。
- 模型选择器平时不常驻展示，只有点击“自定义预设”才弹出。
- 弹窗只负责选择模型，不填写 Key。
- 确认后，模型回到主页面对应能力分组；每张模型卡片直接显示独立 Key 输入框。
- 不同模型可以填写不同 Key；修改一个模型的 Key 不覆盖其他模型。
- Key 默认遮挡，可通过受权限保护的当前查看机制查看；清空 Key 后按现有规则从业务模型下拉移除。
- 地址、API 格式、自定义请求地址、高级开发参数和“添加自定义模型”全部隐藏，后端也必须拒绝管理者提交这些字段。

#### 组员

- 个人中心不显示 API 配置入口。
- 直接使用管理者配置并授权的模型。
- 不返回完整 Key、地址或内部开发参数。

YZCM API 继续作为独立中转站入口，不修改其现有页面和职责。

### 6.8 账号与角色

仅开发创始和获授权开发者可见，按团队分组，不使用一张没有归属关系的扁平总表。

页面顶部展示团队数、账号数、启用数和待处理数，并提供账号、团队、身份和状态筛选。每个团队分组单独显示：

- 团队负责人。
- 剩余能量。
- 本月消费。
- 成员数量和状态。
- 展开后的账号、身份、本月消耗、最近登录和操作。

行内操作按权限显示“切换账号”“重置密码”“调整权限”“停用”等。开发者不能看到任命开发者或修改开发创始的可执行入口；即使伪造请求，后端也必须拒绝。

## 7. 能量数据口径

| 展示项 | 真实含义 |
| --- | --- |
| 剩余能量 | 当前团队绑定的 YZCM 消费账号可用余额，1 能量 = 1 元 |
| 已消耗能量 | YZCM 已核账的实际消费金额 |
| 待核账 | 已产生请求但尚未匹配最终消费日志，不换算虚假金额 |
| 团队排行 | 同一团队成员在指定周期内的已核账消费排行 |
| 所有团队消耗 | 开发创始和开发者可查看的跨团队消费汇总 |

个人中心只做展示和权限内查询，不维护第二套余额。充值、退款、站外调用和人工调整都可能影响 YZCM 钱包，禁止用本地账单反推余额。

成员共享团队配置时，请求仍以真实认证成员归属。账号切换期间，请求归属被切换的目标账号，同时保存真实操作者，避免排障消耗记错人。

## 8. 视觉与动效规范

### 8.1 玻璃体系

- 深海军蓝至黑色动态背景，使用蓝、青、紫、少量洋红的品牌能量粒子。
- 内容卡片保持真实通透，约 45%–60% 深色透明度，并使用背景模糊和细窄青白描边。
- 密集表格与文字区域可增加局部深色衬底，但不能退化成完全不透明的大色块。
- 能量主数字可使用克制的香槟金；成功、警告和错误分别使用绿、琥珀和红。
- 页面装饰围绕品牌 Logo 的能量轨迹，不使用与品牌无关的大型摆件。

### 8.2 动效

- 背景粒子和能量轨道缓慢移动，模拟能量释放，不干扰阅读。
- 身份图标只做轻微呼吸、高光流动或小范围环绕，不能持续大幅旋转。
- 弹窗、折叠组和卡片切换使用短促平滑过渡。
- 遵守系统“减少动态效果”设置；开启后停用背景位移和循环动画，只保留静态高光。

### 8.3 密度与响应

- 桌面端优先，主内容采用 12 栅格组织；表单主区约 8 栏，辅助信息约 4 栏。
- 身份图标约 24–28 像素，不占用独立大卡。
- 1366 像素宽度下不能依赖水平滚动完成核心操作。
- 表格操作过多时保留最常用动作，其余收进“更多”。

## 9. 后端与数据边界

实现时按职责拆分，避免把所有逻辑塞进个人中心页面：

- 身份与授权：角色、开发者授权范围、团队归属和后端权限判断。
- 账号切换：真实操作者、目标账号、有效期、受限操作和审计。
- 能量查询：团队余额、核账消费、排行、跨团队汇总和缓存时间。
- 团队账号：创建、停用、恢复、归档、密码重置和永久删除前置检查。
- 模型目录：YZCM 目录同步、允许范围、能力分类、适配状态和搜索。
- 团队凭据：各模型独立 Key、脱敏显示、保存状态和业务下拉可用性。
- 安全中心：密码、MFA、Passkey、邮箱、设备会话和找回流程。

持久数据使用 MySQL；队列任务使用项目既有 MySQL 任务机制；短期缓存、频率限制和分布式锁使用 Redis；敏感凭据使用现有受保护配置存储，不进入日志、文档或前端状态快照。

## 10. 错误与空状态

- 余额不可用：显示“暂无法获取”、上次成功时间和重试，不显示 0。
- 模型目录同步失败：继续显示上次有效目录和更新时间，不清空已选模型。
- Key 保存失败：保留用户输入但标记未生效，提供明确原因；不得进入业务下拉。
- 权限不足：返回统一无权提示，不泄露目标账号、团队、余额或 Key 是否存在。
- 切换目标已停用：阻止进入并结束无效切换状态。
- 重置密码邮件失败：临时密码仍只允许显示一次，并明确发送失败；不得写入审计明文。
- 没有消费：展示空状态，不生成虚假折线、排行或总额。
- 团队归档存在在途任务或待核账：明确展示影响，按服务规则等待或终止新请求，不删除历史记录。

## 11. 验收标准

### 11.1 权限

1. 四种身份看到的导航、按钮、数据范围与本文一致，直接调用接口也不能越权。
2. 开发创始可以任命开发者；开发者不能任命开发者或修改开发创始。
3. 开发者可以新建团队；管理者只能管理本团队组员。
4. 账号切换范围、持续提示、真实操作者与目标账号审计、消耗归属和敏感操作禁用全部符合第 5 节。

### 11.2 能量与账单

1. 所有身份都能看到所属团队剩余能量和团队成员消耗排行。
2. 开发创始与开发者能查看所有团队消费和逐团队余额，但页面不显示跨团队合计钱包。
3. 余额、明细、排行和导出使用同一真实数据口径；未知金额不补零。
4. “补充能量”只进入 YZCM API 既有流程，不生成第二套充值或扣款记录。

### 11.3 API 配置

1. 当前平台预设、能力分组、Key 自动保存、额度刷新和附加配置没有因改版丢失。
2. 管理者点击“自定义预设”后只能搜索和选择 YZCM 模型，平时不常驻显示模型选择器。
3. 选中模型返回主页面后，每个模型卡片直接显示自己的 Key 输入框；不同模型可保存不同 Key。
4. 管理者看不到地址和“添加自定义模型”，伪造请求也不能写入地址或开发参数。
5. 开发创始和获授权开发者仍可使用完整自定义模型能力；组员不显示 API 配置。

### 11.4 安全与账号

1. 修改密码、TOTP、Passkey、邮箱验证、设备会话、退出其他设备和找回账号均走真实后端流程，不使用装饰性假按钮。
2. 管理员重置密码的范围、临时密码、强制改密、旧会话撤销和审计符合第 6.5 节。
3. 停用和归档可恢复且不丢账单；永久删除只允许开发创始，并正确阻止危险删除。
4. MFA 敏感信息未完成受保护存储前不得标记生产验收通过。

### 11.5 视觉与本地验证

1. 账户总览、个人资料、能量与账单、安全、团队、API 配置和账号与角色使用同一玻璃视觉体系。
2. 动态背景不影响文字可读性，“减少动态效果”可正确关闭循环动画。
3. 身份图标紧邻名字并保持小尺寸，正式身份名称始终使用四个约定名称。
4. 实施后先在本地 4001 完成登录、真实权限、页面、接口、刷新持久化和 Go embed 运行验收；未完成本地验收不得发布。

## 12. 明确不做

- 不修改 YZCM API 中转站现有功能。
- 不新增第二套钱包、积分或支付系统。
- 不保留虚假会员等级、会员权益或安全分数。
- 不让管理者填写请求地址或添加自定义模型。
- 不让组员管理 API Key。
- 不把多团队余额相加成一个可用余额。
- 不依赖前端隐藏实现权限控制。
- 不在本设计阶段修改功能代码、构建或部署。

## 13. 建议实施顺序

1. 统一身份、授权范围和账号切换后端边界。
2. 接入团队能量、消费、排行和跨团队查询。
3. 重构个人中心导航与页面骨架，删除会员中心重复入口。
4. 按真实页面改造 API 配置及 YZCM 模型目录选择。
5. 完成账号安全、找回与管理员重置密码。
6. 完成团队归档、账号停用和账号与角色页面。
7. 统一玻璃视觉、身份图标和动态背景，并加入减少动态效果。
8. 在本地 4001 进行角色矩阵、数据口径、错误状态、刷新持久化和 Go embed 端到端验收。
