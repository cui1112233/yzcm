# 个人中心退出登录与账号切换设计

日期：2026-11-28  
状态：待用户书面确认

## 目标

个人中心必须让用户随时找到并使用三个互不混淆的动作：

1. 返回工作台；
2. 退出登录，结束当前登录会话；
3. 切换到有权限代操作的账号，并能随时退出切换返回本人账号。

同时修复个人中心内容过长后无法上下滚动、侧栏底部操作被挤出屏幕的问题。

## 已确认的交互

### 侧栏和页面滚动

- 左侧栏保持一屏高度，分成资料区、导航区、底部操作区。
- 资料区固定在顶部。
- 只有中间导航区独立上下滚动。
- “返回工作台”和“退出登录”固定在侧栏底部，任何窗口高度下都不需要先滚到底。
- 右侧主内容区独立上下滚动，长表单、长列表和 API 设置都能滑到最后一项。
- 窄屏下侧栏收窄为图标栏，但底部两个动作仍保留图标、提示文字和可点击区域。

### 退出登录

- “退出登录”固定放在左侧栏最底部，位于“返回工作台”下方。
- 点击后沿用现有真实登出接口，清除登录会话并回到登录页。
- 退出登录与退出账号切换是两个不同动作，不共用按钮或文案。

### 账号切换下拉

- 顶部“切换账号”点击后立即展开下拉，不要求用户先输入用户名。
- 下拉打开时直接展示当前操作者有权切换的账号。
- 下拉顶部支持按显示名称和用户名搜索；搜索只过滤后端已经授权返回的选项。
- 每个选项显示头像、显示名称、`@用户名`、身份和所属团队。
- 账号按团队分组；没有团队的可切换账号单独分组。
- 当前本人账号、停用账号、归档账号以及无权切换的账号不显示。
- 选择目标后显示明确的确认动作，避免误点立刻切换。
- 取消原来的“手动输入目标账号用户名”交互。
- 无可切换账号时显示空状态；读取失败时显示错误和重试，不退化为任意用户名输入。

### 退出账号切换

- 切换成功后，页面顶部持续显示“正在以某账号操作”。
- 状态条提供“退出切换”，点击后返回操作者本人的账号。
- 侧栏底部“退出登录”仍然可见，用于彻底退出系统。
- 两个动作的文案固定为“退出切换”和“退出登录”，避免用户误解。

## 权限边界

后端仍是唯一权限判断来源，前端不自行推算可切换名单：

| 当前身份 | 下拉中允许出现的账号 |
| --- | --- |
| 开发创始 | 所有符合服务端代操作策略的开发者、管理者和组员账号 |
| 开发者 | 自己获授权管理团队中的管理者和组员 |
| 管理者 | 自己团队中的有效组员 |
| 组员 | 不显示切换入口 |

现有禁止项保持不变：不能切换到自己，不能切换到停用或归档账号，开发者不能切换开发创始，管理者不能切换其他团队账号。

## 技术设计

### 后端

在现有账号切换服务下增加只读目标接口：

`GET /api/account-impersonation/targets`

接口从账号中心真实身份、团队成员关系和授权记录生成列表，并对每个候选账号复用 `accountcenter.Policy` 的 `ActionImpersonate` 判断。响应只包含下拉需要的公开字段，不返回密码、密钥、邮箱、手机号或完整治理目录。

响应结构固定为：

```json
{
  "groups": [
    {
      "teamId": "team-1",
      "teamName": "一战晟铭",
      "accounts": [
        {
          "username": "member-a",
          "displayName": "组员甲",
          "role": "member",
          "avatarUrl": ""
        }
      ]
    }
  ]
}
```

接口必须禁用缓存，并在每次读取时重新校验当前操作者和目标状态。真正执行切换时，现有 `POST /api/account-impersonation` 仍再次校验权限，不能把下拉列表当成授权凭证。

### 前端

- 账号切换入口读取目标接口并展示可搜索下拉。
- 搜索匹配 `displayName` 和 `username`，忽略大小写和首尾空格。
- 选择账号后调用现有 `startAccountImpersonation(username)`，成功后沿用现有跨标签页通知和整页刷新。
- 切换状态条继续调用现有 `stopAccountImpersonation()`。
- 侧栏使用“固定顶部 + 可滚动导航 + 固定底部”的三段式布局；主内容区保留独立滚动。

## 错误处理

- 目标列表读取失败：下拉显示“无法读取可切换账号”和“重试”。
- 目标在确认前被停用、归档或移出团队：执行切换由后端拒绝，前端显示真实错误并刷新下拉。
- 当前切换已失效：沿用现有状态刷新机制，清理切换状态并返回本人账号。
- 登出失败：保留当前页面并显示错误，不伪装成已经退出。

## 测试与验收

### 自动测试

- 后端测试四种身份的目标列表范围。
- 后端测试停用、归档、本人和越权账号不会进入列表。
- 后端测试列表读取与实际切换都独立执行权限校验。
- 前端测试下拉初次打开就有选项，不需要输入才能加载。
- 前端测试按显示名称和用户名搜索。
- 前端测试空状态、失败重试、确认切换和退出切换。
- 布局源码测试固定底部退出登录、导航滚动和主内容滚动。

### 浏览器验收

- 低高度窗口下，“返回工作台”和“退出登录”始终可见。
- 侧栏菜单和右侧长页面都能分别滑动到末尾。
- 管理者打开下拉立即看到自己团队的组员，并可搜索。
- 开发创始和开发者只看到各自权限范围内的账号。
- 组员看不到切换入口。
- 切换后“退出切换”和“退出登录”同时存在，含义和结果不同。

## 不在本次范围

- 不改变现有四级身份名称。
- 不改变代操作有效期和审计规则。
- 不允许在下拉外手动输入任意用户名。
- 不修改密码、MFA、API 密钥和团队角色的既有安全限制。
