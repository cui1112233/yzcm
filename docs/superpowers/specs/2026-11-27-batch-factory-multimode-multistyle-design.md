# 批量工厂：新建多模式项目与多画风输出

日期：2026-11-27。状态：用户已确认整体设计及最多5种画风，进入实施计划阶段；尚未实施或发布。

## 已确认需求

- 漫画项目可选择1～5种不同画风，复用同一套故事、分镜和对白，每种画风独立出图、合成合集并上传。多画风始终在同一个作品项目内创作，不按画风复制作品项目。
- 在媒体库“漫画页”中选择画风，查看该画风的页面；“合集”中同样按画风切换，每种画风分别拥有合集和上传状态。
- 一个自动化预设保存同一套漫画提示词配置和多种画风选择。
- 仅在“新建批量”支持多模式选择：视频生成、漫画生成、文字插画、文本生成。可勾选任意一项或多项。
- 勾选四项就创建四个独立作品项目，各项目包含同一批书，不将四种任务混进一个作品项目。
- 创建时复用书单、原文、男女频和类型结果；创建后分别保存，各项目的手动修改互不影响。该独立修改方式已由用户明确确认。
- 各项目继续按自己的配置、预设和执行模式生产。现有单模式入口与执行能力需要保留。

## 两层结构

第一层为作品项目：视频、漫画、文字插画、文本各自独立。

第二层为项目内的画风输出：例如漫画项目选择水墨、国风、写实，仍是一个漫画项目，但每本书拥有三套图片、三份合集及三份上传回执。最多选择5种画风；选择5种仍只创建一个漫画作品项目。

示例：同一批10本书，创建四个项目，漫画选择三种画风、其他项目各输出一套，则每本书计划六套成果。实际页数和计费按各项目的真实任务统计，不以四个项目直接推算费用。

## 新建批量界面

- 沿用现有作品名称、书城、书单输入和整体主题。
- 生产模式改为四项可勾选选项；默认保持现有单模式行为。
- 每个已选模式展示自己的自动化预设选择及统一配置入口，切换编辑时保留其他模式已填写的值。
- 漫画项目的统一配置和单书配置使用同一个多画风选择组件；单书默认继承项目选择，可明确覆盖。新建批量、统一配置、单书配置、预设保存与载入均应用1～5种的相同限制，显示“已选3/5种画风”；同一画风不能重复选择。达到5种后可取消或更换，不可再添加第6种。
- 自动化预设仍按所属模式保存与校验；一个视频预设不覆盖漫画或文本配置。多模式创建保存各模式到其所选预设的对应关系，不强制新增另一套“总预设”体系。
- 提交前展示将创建几个项目，以及每种模式已选预设、执行方式、画风套数。显示可确认的数据，不假定生成张数等于最终张数。
- 生成项目名称默认使用“用户填写名称 · 视频/漫画/文字插画/文本”，作品卡片使用对应类型标识。
- 已创建项目中不新增多模式勾选入口；其配置与任务继续以当前项目为范围。

## 创建和共用数据

1. 一次提交记录一份书单来源和稳定的创建请求标识；重复点击、网络重试不能再创建另一组相同项目。
2. 每本书的原文获取与分类只执行一次，成功结果保存后分发到本次选中的项目，不为四个项目各调用一次分类。
3. 已有有效男女频和类型直接复用；失败保留原因，通过明确的人工重试处理，不因模式数量增加而重复触发分类。
4. 保存完整原文，各模式再按自己的截取、分页、分镜配置处理；视频的截取值不能限制文本项目的原文。
5. 分发保存后，每个项目拥有独立书籍记录与配置。后续修改某个项目的正文、男女频、类型、预设或任务，不改写同组其他项目。
6. 允许原文导入异步完成：尚未分发的项目等待对应书籍结果，不自行再拉取或分类。完成分发后不持续同步。
7. 页面刷新后能找到已创建的项目及导入进度；创建失败展示已完成和未完成的项目，恢复时只补未完成部分，不复制已完成项目。
8. 复制的范围是书籍来源和基础信息，不复制历史执行任务、生成图片、上传成功状态或上传回执。

## 各模式的生产边界

- 视频：使用自己的模型、音频、分镜、合成、上传流程。
- 漫画：使用漫画分页和提示词预设，支持本项目内多画风输出。
- 文字插画：独立项目和类型标识，使用现有“CM·文字插画版”生成能力。当前代码内部属于漫画预设，不直接添加一个后端尚不接受的 productionMode 值。配置、预设加载、刷新恢复和发布时必须持续保留“文字插画”身份。
- 文本：使用自己的分页、字体、背景、标红及合集流程。
- 不同模式分别生成适合自己的提示词与分段；只在同一模式的多画风输出中复用中性的故事和分镜内容。
- 第一版明确交付漫画多画风；文字插画保留现有画风配置，不擅自把视频、文本等所有风格字段都改为多选。若需要文字插画多画风，可复用该能力扩展，须在实施范围中明确。

## 多画风生成

- 服务端同样校验有效配置中的画风数量和身份，不能仅靠界面限制。旧的单画风配置按一项读取；超限请求明确报错，不静默丢弃用户选择。
- 单选一个画风等同现有行为。选择多种画风时，每种画风有稳定身份、名称及本次执行配置快照。
- 共用故事、人物设定文字、分镜和对白；后端 prompt 模块按画风分别组合画风描述、约束及参考图，不在前端硬编码提示词正文。
- 已带有某种画风的成品提示词不能直接复用到另一画风；共享部分需保留可重新组合的中性内容。
- 人物外观设定可复用；带特定画风的角色图片或参考图片按画风分别管理，不能将一种画风的参考自动绑定全部画风。
- 图片、当前主图、候选版本、合集、任务状态、失败原因与上传回执均区分画风。生成另一画风不得覆盖已成功的图片。
- 合集只取本画风的有效主图，顺序遵循该书分页；不能混入其他画风或其他模式的页面。
- 失败重试仅处理对应画风的缺失或失败步骤；已有成功图片和成功上传回执保留。重试上传不能顺带重新出图。
- 修改配置后标记受影响成果；已经运行的任务使用原快照，后续明确更新时才按新配置生产。
- 取消某个已生成的画风不自动删除其图片、合集或网络成果。

## 同一项目内的媒体库展示

- 保持现有“漫画页”和“合集”的布局、组件及整体主题，在现有工具栏加入画风选择，例如“画风：水墨”。不另开一套按画风划分的作品列表。
- “漫画页”仅展示当前选择画风的图片、候选版本、当前主图和生成状态。切换画风只切换查看范围，不触发生成、合成或上传。
- 切换画风尽量保持同一正文页的位置；若对应页尚未生成，显示该画风该页的真实状态，不能拿其他画风的图片填充。
- “合集”沿用当前选中画风，支持切换到其他画风，分别展示该画风的合集、页数、合成状态和上传回执。查看全部画风的总完成度时，必须与当前画风的页数和状态明确区分。
- 本页生成、候选切主图、合成当前书及上传等操作使用界面当前所选的画风身份；批量自动生产按本次任务保存的画风列表执行，不随用户切换查看画风而改变。
- 画风切换后迟到的加载响应不能将图片、进度或操作目标覆盖回前一个画风。

## 合集、上传和进度

- 每个项目、每本书、每种画风分别维护成果和上传状态。同一本书的不同模式或画风是不同成果，不能被正文相同的去重规则误拦截。
- 同一成果的重复请求沿用现有防重复上传能力；用户明确“再次上传”仍按现有提示规则处理。
- 建议保留现有 AIGC 前缀、上传人和北京时间月日，在名称中加入模式及必要的画风后缀，例如“AIGC-邱琬晶1127-不宠-漫画-水墨”。单模式单画风维持原命名，避免无关改名。
- 名称长度限制必须给模式、画风和书名预留空间，不截断辨识后缀；名称不是内部唯一标识。
- 每个项目展示自己的书数、计划/已生成张数、画风套数、合集数和上传成功数。
- 一书三画风上传两套时显示2/3，不将整书报告为全部完成。同组其他项目的失败不阻止本项目继续。
- 页数封顶沿用各模式自己的配置，漫画按每种画风单独应用，不将三种画风共用一个35页总额。

## 并发、费用与恢复

- 所有项目和画风使用现有全局容量控制及 Redis 排队，不能因四个项目各自启动而把同一上游额度放大四倍。
- 共用的是原文和分类结果，不代表多风格图片免费。图片、视频、配音、AI处理按实际调用记录归属到成员和相应任务，不重复记账。
- 本设计不调整模型价格，不新增可绕过限额的并发开关。
- 任何付费实测另按用户明确授权执行；开发测试先用模拟供应商验证流程。
- 重启恢复按项目、书籍、画风及步骤识别未完成项，不能重跑整组或重复上传已经成功的合集。

## 验收范围

- 单模式、单画风现有项目可正常读取、配置和执行。
- 四项全选创建恰好四个项目；同一请求重发不重复创建。
- 同一书分类只调用一次；分发结果一致，创建后的修改互不影响。
- 漫画提示词分析一次，三画风图片互不覆盖、合集互不混页，失败恢复只补对应缺失项。
- 选择1种或5种画风都只产生一个漫画作品项目；第6种在界面、接口及预设载入时均不能成为有效配置。
- 在漫画页和合集间切换画风可看到各自的真实成果及状态；切换本身不发起收费生成或上传，所有后续操作准确作用于当前画风。
- 四种模式均可通过自己的预设、统一配置和执行方式继续任务；文字插画不会恢复成普通漫画标识或错误模式。
- 刷新、断线、进程重启及部分项目创建失败后可恢复，成功回执保持稳定。
- 同时提交多项目仍受相同上游容量限制；统计按真实结果更新。
- 先完成本地4001验收。远端推送、上线、Mac运行包更新均需后续明确安排；本次设计整理不执行这些动作。
