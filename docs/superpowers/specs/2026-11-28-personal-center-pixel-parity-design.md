## 3. 视觉规范

### 3.1 场景与方向

- 场景：高密度操作型个人中心。
- 方向：精致的未来能量控制台。
- 画面必须同时具有深蓝空间感、通透玻璃层、高亮能量轨迹和少量金色身份强调。
- 品牌已有蓝紫能量视觉，因此允许使用参考图中的蓝紫光效；不得退化为普通紫色后台模板。

### 3.2 颜色与材质

- 个人中心必须与工作台使用同一套玻璃语言，不能再形成一套独立的“蓝色个人中心皮肤”。
- 页面底色来自动态蓝紫能量背景；卡片本身使用无色烟晶玻璃，不主动铺大面积蓝色。
- 一级玻璃建议使用中性灰黑 `rgba(5, 9, 18, 0.18)` 至 `rgba(11, 16, 28, 0.28)`。
- 二级玻璃和输入区可提高到 `rgba(8, 13, 24, 0.28)` 至 `rgba(15, 22, 36, 0.38)`，只用于保障文字可读性。
- 禁止继续使用 `rgba(17, 39, 84, 0.62)` 至 `rgba(28, 53, 108, 0.78)` 作为大卡片主体色；这会把玻璃变成不透明蓝色面板。
- 青色能量高光 `#4DDCFF` 和蓝色结构光 `#768BFF` 只用于动态背景、选中状态、主按钮、图标和边缘冷光。
- 金色身份强调使用 `#F6D48B`，成功状态使用 `#58E6A9`，危险操作使用 `#FF7189`。
- 玻璃感主要由背景透视、18–28 像素模糊、低饱和度、顶部细反光、内侧高光和一像素冷光描边共同形成，而不是由蓝色填充形成。
- 背景能量经过卡片后必须仍然肉眼可见，并呈现柔和模糊和轻微折射；多层卡片嵌套时不得越叠越蓝。

### 3.3 字体与数字

- 中文正文优先使用 `HarmonyOS Sans SC`，回退到 `Source Han Sans SC`、`Microsoft YaHei`。
- 标题使用较宽字距和清晰的粗细层级。
- 能量、余额、消耗、日期和排名数字使用等宽数字特性 `tabular-nums`。
- 不把文字做成图片；所有业务文字保持可访问、可选择和可响应。

### 3.4 总体布局

- 顶部品牌栏目标高度 56–60 像素。
- 宽屏左侧栏目标宽度 220 像素。
- 内容区使用剩余宽度，不套居中窄容器。
- 页面间统一使用 4/8/12/16/24/32 像素间距阶梯。
- 页面主体使用统一的十二列流式网格；同一行的卡片共享列线、顶部基线、底部基线和间距，不允许各页面自行估算宽度。
- 删除基于 `zoom: 1.125`、`zoom: 1.5` 的大屏整体放大方案。缩放会让边框、滚动区域、列宽和屏幕实际尺寸错位。
- 宽度、内边距、头像、标题和控件尺寸使用 `clamp()`、百分比、`minmax()` 和容器可用宽度平滑变化。
- 宽屏采用参考图的左右分栏；中屏调整列宽比例；窄屏按信息优先级改为单列，禁止横向溢出和内容裁切。
- 成对卡片默认 `align-items: stretch`，保证同排外框上下对齐；内容较少的一侧使用内部留白，不改变外框基线。
- 长页面只滚动右侧主内容区，顶部栏和左侧导航保持稳定；API 配置等展开后必须可以滑到最后一个设置项。
- 使用宽屏、中屏、窄屏三类布局规则，但不在断点处改变玻璃材质和视觉身份。
- 宽屏优先还原 1672×941 与 1678×937 参考图，同时验收 1440×900、1280×800 和窄屏重排。

## 4. 背景和动态能量

- 使用一战晟铭品牌 Logo 与能量轨迹的独立图片资产构成背景，不用几条普通 CSS 圆线代替。
- 背景是全屏连续场景，不为每张卡片重复创建蓝色底图。它包含左下、右上和内容区域后的能量流，亮度必须低于文字和交互控件，但穿过无色玻璃后仍肉眼可见。
- 动态背景分为三层：低速漂移的远景星尘、缓慢流动并轻微缩放的蓝紫能量带、少量近景柔光粒子。
- 粒子数量按屏幕和设备能力调整；宽屏显示完整层次，中屏减少近景粒子，窄屏只保留低密度星尘和一条能量流。
- 粒子和能量带只使用 `transform` 与 `opacity` 动画，避免引发频繁重排；不能覆盖按钮、输入框或文字，也不能跟随每张卡片重复滚动。
- 允许极轻的鼠标景深差，但卡片本身不晃动，背景位移幅度不得影响阅读。
- 动态只包含缓慢流动、局部粒子闪烁、玻璃高光漂移和身份徽记呼吸。
- 不使用持续快速旋转、大幅缩放或影响阅读的动画。
- `prefers-reduced-motion` 下停止粒子位移、能量漂移和徽记旋转，保留静态背景与边缘高光。

## 5. 图标设计

### 5.1 通用功能图标

- 导航、标题、表单、模型类型和操作按钮使用统一的 24×24 品牌线性图标体系。
- 线宽、圆角、透视和能量高光统一；默认白蓝线条，选中时出现青色外发光。
- 图标应由正式资产或统一图标组件提供，不使用 emoji、文字符号或临时占位图形。
- 首页、人物、能量、盾牌、团队、代码、外链、模型、钥匙、设备、排行、账单等图标均需逐一对齐参考图语义。

### 5.2 四种身份徽记

四种正式身份均使用一战晟铭 Logo 语言重新设计独立徽记，不使用通用皇冠或盾牌替代：

- **开发创始**：金色恒星核心、青蓝品牌翼形和双层能量轨道，权重最高。
- **开发者**：蓝紫双翼能量结与明亮核心，表现研发权限。
- **管理者**：青蓝角状品牌轮廓与稳定环形核心，表现团队治理。
- **组员**：精简的蓝色流线品牌符号与单层能量核心，保持识别度但不过度抢眼。

资产要求：

- 每个身份至少输出透明背景主资产和 24、32、48、64 像素适配版本。
- 小尺寸下必须仍能区分四种身份，不能只依靠颜色。
- 用户名旁使用 24–28 像素版本；表格可使用 24–32 像素版本；详情场景最多 48 像素。
- 动态由轻微呼吸、核心亮度变化和小范围流光组成；徽记本体不持续大幅旋转。
- 资产保存到项目正式品牌资源目录并进入 Git，不能依赖临时目录或外部链接。

## 6. 九个页面/状态的还原范围

### 6.1 账户总览

- 还原左侧身份区、顶部身份卡、可用能量主卡、消耗趋势、成员排行榜、YZCM 连接、模型可用情况和最近账单分区。
- 所有金额和排行榜只来自真实接口；无数据时保留卡片结构并显示设计过的空状态。

### 6.2 个人资料

- 还原顶部横向身份名片、左侧基础资料、右侧账号归属和资料使用范围。
- 身份徽记紧邻用户名，不创建大型独立身份卡。

### 6.3 账号安全

- 还原登录与验证、找回账号、登录设备、安全活动四个区域。
- 只显示已接通的能力；未接通的 MFA、Passkey、设备管理必须明确显示未设置、暂不可用或规划中，不能做成可成功操作的摆设。

### 6.4 团队管理

- 还原团队概要、成员筛选、成员列表、能量排行、最近管理操作和重置密码弹窗。
- 表格密度、行高、按钮组和侧栏比例按参考图执行。

### 6.5 全平台团队消耗

- 仅开发创始和开发者可进入。
- 还原平台指标、趋势、团队排行、团队余额表和右侧详情栏。
- 团队余额独立展示，不计算虚假的平台总余额。

### 6.6 API 配置管理者主页面与模型弹窗

- 管理者只选择 YZCM 模型并填写 Key。
- 模型地址保持隐藏。
- 模型按文本、图像、视频、语音、多模态分组，Key 直接显示在模型卡片中。

### 6.7 API 配置开发创始主页面

- 开发创始和开发者可添加自定义模型、地址、模型标识和多个 Key。
- 自定义字段仅在对应模型卡片展开时出现，不常驻铺满页面。

### 6.8 账号与角色

- 还原总览指标、搜索筛选、按团队折叠分组、账号切换、重置密码和权限调整操作。
- 四种身份名称固定为：开发创始、开发者、管理者、组员。

## 7. 功能与数据边界

- 一比一指页面、状态、交互和像素层级对齐，不代表伪造设计图中的示例数据。
- 现有接口和权限是功能真相；缺少的数据用明确空状态表达。
- API 配置不重写 YZCM API 中转站，只展示和配置当前系统已授权能力。
- 不硬编码真实 Key、余额、电话号码、邮箱或成员名单。
- 不为了视觉还原改变后端角色权限。

## 8. 实现边界

- 先清理个人中心样式文件中互相覆盖的历史规则，再建立唯一视觉层；禁止继续在文件末尾叠加补丁式 CSS。
- 先抽取并复用工作台的玻璃材质参数，再为个人中心增加能量背景，不允许复制后另调成另一套蓝色参数。
- 建立一级玻璃、二级玻璃、输入玻璃、悬浮玻璃、选中态和危险态六种有限材质令牌；页面组件只能使用令牌，不得自行写一套蓝色渐变。
- 建立统一十二列布局和页面容器规则，清除固定宽度、任意最小高度和 `zoom` 放大造成的错位。
- 共用外壳、玻璃卡片、指标卡、数据表、空状态、身份徽记和模型卡片拆成独立组件。
- 页面业务请求和权限判断优先复用现有实现。
- 图片资产必须进入源码资源目录；构建产物只由 React 构建和 Go embed 脚本生成。

## 9. 一比一验收

每张参考图必须使用相同桌面视口和相同页面状态，与 4001 实现截图并排比较。

验收拆成四层：

1. **页面**：九个页面/状态全部存在，区块顺序和列宽一致。
2. **状态**：加载、空数据、已配置、未配置、展开、弹窗、无权限状态均可见且真实。
3. **交互**：导航、筛选、展开、保存、清除、切换账号、重置密码等现有功能可用。
4. **像素**：背景、玻璃、描边、高光、图标、字号、行高、间距和响应式布局与参考图对齐。

除九张参考图外，还要进行一次工作台统一性对比：个人中心玻璃的透明度、颜色中性程度、边缘高光和背景透视必须与当前工作台一致。个人中心可以拥有更明显的蓝紫能量背景，但卡片材质不能变成蓝色实体面板。

响应式验收至少覆盖 1678×937、1440×900、1280×800 和一个窄屏尺寸。每个尺寸都检查列线对齐、成对卡片上下边缘、内容滚动、输入框不溢出和导航稳定性。

为每张图生成设计 QA 记录。P0、P1、P2 差异必须修完；只允许把不影响识别和使用的 P3 微调留到后续。没有九张参考图与九张实现截图的并排证据，不得声称一比一完成，也不得推送上线。
