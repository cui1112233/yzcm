## 推荐设计

### 任务与运行状态

任务文档表示每本书的数据，Redis 表示仍在排队或执行的任务，运行记录表示历史经过。接口返回历史记录时必须核对实际队列，不把历史 queued 直接当成当前执行；原队列已不存在且没有有效任务依据时标明运行记录失效，提示可人工重新开始。不得自动把 1869 条旧记录重新入队。

核对须覆盖 queue_、go-workshop-、定时任务等入口，避免仅按某一前缀修正。Redis 不可达属于“无法核对”，不能当成“任务不存在”。不得仅凭时间久就终止仍然有效的任务。

前端统一使用核对结果，空批次显示“当前批次没有任务”，没有实际运行任务显示“暂无正在处理的任务”。最新任务为空时清除旧显示，不保留上一次 queued 的提示。

### 指定书籍恢复

仅恢复本次明确排查的书号。先检查备份哈希与数据库正文，再以事务重建最小任务关联并保留原文、处理后正文、AI1 的实际内容。若操作期间已有新文档，停止恢复，不覆盖。

恢复后的正文重新转为可用状态并清除回收期限。缺失的原任务创建时间、分类、模型、批次和上传回执不得编造。恢复时间单独记录；书名可使用当前输入区已知值并注明来源，分类待人工确认。已有 AI1 标为可查看成果，不标为已上传，也不自动上传。

不批量恢复其他孤立正文：它们可能属于用户有意删除的任务。历史批次不会根据旧 run ID 和正文反向编造；本轮仅明确提示旧批次没有可关联任务。

### 新任务与提交

沿用参考源码的关键规则：先保存任务、立即可见，再抓取和处理；保存完整原文，再按 maxTxt 形成处理正文；AI1 等版本独立保存；最终提交以目标网站可核对结果为准。

先用不收费的替代服务和现有回归测试验证阶段流转、重启恢复、重复请求不重复入队。真实模型调用、付费重试和外部上传不包含在本轮默认验证范围中；需要真实端到端验收时，须明确书号、版本、模型和上传范围。
