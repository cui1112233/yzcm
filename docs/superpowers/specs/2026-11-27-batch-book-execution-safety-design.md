# 批量测书剩余修复与统一更新设计

日期：2026-11-27。依据用户已确认报告及本轮“先解决，然后在统一更新”的授权执行；不再逐项更新 4001。

## 完成标准

先修完报告剩余的正文加载、字数同步、重复生成、停止与重试竞态、队列误判、重试上限、错误空转和重复全量扫描，再统一验证和更新。保留第一批正文保护。源码始终维护在 v88，保留其他任务的未提交修改，不新建分支、不推送、不公开部署。

统一更新默认指本地 4001。更新前检查其他运行任务；不以真实付费重试做验证，不中断已有付费任务。若仍有运行批次，保留已验证候选并核验能否安全切换，不能把“构建完成”说成“4001 已更新”。

## 方案取舍

采用现有 Go/MySQL/Redis 的共同入口、存储与队列能力。继续逐点补显示会遗漏执行保护；新建通用工作流或新抓书框架没有必要。原文仍走已有 HTTP 上游，不引入浏览器。

### 正文与任务一致

新增共用正文读取方法，正文记录优先，仅不存在时兼容旧字符串字段或明确 text 字段；读取出错不退回旧内容。改文入口、执行入口复用该方法，不因任务仅保存引用而重新抓书。

保存正文在同一存储锁或数据库事务内同步现有任务的 bodyRefs、版本、指纹和字数；不把正文重复塞入摘要。后续旧 document 的保存也必须合并当前真实正文引用，避免重新覆盖新字数或把旧内嵌文本迁回正文。只读每本书的少量引用，不全量下载正文。

### 执行入口与停止

直接生成改为持久排队，返回 queued、job_id、task 和“已进入后台生成队列”，前端不能显示已经生成完成。新增 GenerateOnly 标记，只处理已有原文的指定 AI 版本，不抓书、不重分类、不上传；该标记进入执行快照并在明确手动重试时保留。

启动、手动重试、直接生成和停止共享每书短时准入保护；模型调用在队列工作线程执行，不占用 45 秒准入锁。任务更新使用现有 CAS，较晚停止不得被较早重试覆盖。清除停止标记只能针对本次明确重试所观察到的旧停止。

运行判断必须核验实际队列。任务表显示 queued 但队列确认不存在时允许恢复；Redis 无法核验则阻止重复排队并报告原因，不能当作空队列。重复请求不能生成两个执行名额或重复调用模型。

### 重试预算

继续使用 retry_schedule，attempt 表示本阶段已失败执行次数，包含首次。普通阶段第三次失败转人工；已确认的 AI 输出错误最多一次补救，至少等待 30 秒。分类失败转人工，保留自动分类一次的既有约定。

原文抓取保留既有首次加最多五次自动重试；配置、登录、无效来源直接人工。AI 或上传超时、断联且结果不确定时不自动重发，上传有 pending_confirmation 时优先已有回读。

预算持久保存，不随工作线程重启、扫描或新 job_id 清零。首次失败时间用于已知的 24 小时预算期限；旧数据没有时间则不编造日期，仍按已知失败次数限额。明确手动重试才开启新轮次。某阶段成功仅清本阶段，不清掉其他阶段的失败预算。

队列获取立即报错使用可取消退避，最大 30 秒并错开重连；正常阻塞等待超时不当成故障。扫描优先轻量候选摘要，移除双重全量读取，正文按需读取。保留现有定时与恢复能力，不额外建立延迟队列。

### 页面与旧迁移恢复

统一识别 done/failed/stopped/cancelled 等终态，停止后及时结束等待。后台生成显示排队状态。既有较低频的页面刷新方案与执行等待保持一致，避免每秒重新读取整批正文。

已复现的历史 1100017 时长字段迁移补恢复入口：仅补缺失字段，核验已存在字段类型和默认值；不修改原 SQL 与校验标识，不靠忽略重复字段冒充成功。同类 1100018 一并覆盖。全应用空库初始化速度与其他未确认迁移不借机重构。

## 验证与发布顺序

以已归档失败诊断和新故障测试先失败后通过；内存与真实隔离 MySQL 分别验证。重点检查：同书只执行一次、仅引用正文能改文、新停止优先、队列错误不重复排队、字数引用一致、超限零外部调用、重启预算不重置、未知上传不重发、扫描不读取正文、迁移部分执行后可继续且旧校验不变。

所有源码先提交 v88。最终从确定提交独立构建前后端与 Go embed，在隔离端口以测试账号验证；一次本地 4001 更新后检查 health、runtime-build-info、正文读取、队列与新前端提示。任何未切换或未完成的范围明确记录。
