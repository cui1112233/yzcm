# 小程序公共页动态背景折射设计

## 状态与取代关系

本设计取代 `2026-10-24-liquid-background-refraction-design.md` 中使用固定 `lens-light.png`、`lens-dark.png` 重复模拟折射的方案。固定圆弧贴图已被运行截图证明会在每张卡片中重复同一形状，不属于背景折射，后续不得继续用于公共页玻璃卡片。

## 目标

在微信小程序的五个公共页面中实现与页面背景连续对应的动态折射：卡片后方的冰蓝壁纸在穿过玻璃边缘时发生局部位移、放大和轻微色散，卡片中心保持通透，页面滚动时折射与背景连续同步，不在停止滚动后突然出现。

用户可感知的成功标准：同一条背景光带进入卡片前、卡片内和离开卡片后保持几何连续，只在玻璃边缘发生弯折；不同位置的卡片显示各自对应的背景片段，不再重复同一圆弧纹理。

## 范围

### 启用动态折射

- 工作区 `pages/workspace/index`
- 任务 `pages/tasks/index`
- 功能 `pages/functions/index`
- 我的 `pages/profile/index`
- 个人资料 `pages/profile-detail/index`
- 上述页面的公共底部导航

### 不在本次范围

- 登录页、登录框、入场视频、人物和轮子动画
- 剧本生成、小说获取、水货生产、批量工厂等业务内页
- 业务数据、接口、会话、权限、导航结构和交互流程
- WebGL、Skyline 或渲染器迁移

## 方案选择

采用“每个公共页面一个全屏同层 Canvas 2D”的方案，保留当前 WebView 渲染器。

不采用以下方案：

- 固定 PNG 贴图：无法依据卡片位置采样真实背景，会形成重复假圆弧。
- 每张卡片一个 Canvas：原生节点和生命周期过多，容易增加内存、测量和页面卡顿风险。
- WebGL shader：折射更接近物理效果，但兼容性、上下文丢失和真机内存风险高于当前需求。
- Canvas 导出临时 PNG：滚动期间必须等待截图和文件写入，会产生“滑动时消失、停止后闪现”的迟钝感。

## 架构

### `DynamicGlassCanvas`

每个目标页面只挂载一个全屏、不可点击的 Canvas 2D 装饰层。它负责：

1. 在离屏 Canvas 绘制与页面一致的冰蓝壁纸。
2. 将壁纸复制到可见 Canvas，作为页面背景。
3. 接收当前视口内玻璃卡片的矩形位置。
4. 对每个矩形直接采样离屏壁纸，并在边缘区域绘制位移后的扫描线。
5. 绘制细亮边、内侧暗线和极轻微色散，表达玻璃厚度。

Canvas 设置 `pointer-events: none`，原生文字、按钮、头像和输入控件始终位于其上方，点击与无障碍语义不由 Canvas 承担。

### `GlassSurfaceRegistry`

公共页中的折射卡片通过稳定的选择器或注册标识进入测量集合。注册表只记录几何信息与视觉等级，不保存业务数据。

每次布局建立、窗口尺寸变化、主题变化或内容结构变化后重新测量。滚动过程中不重复查询全部节点，只使用已缓存的文档坐标和最新滚动位置换算视口坐标。

### 纯绘制核心

从 `pages/glass-lab/refraction2d.ts` 提取纯绘制逻辑，形成不依赖 React 的几何与绘图模块。核心输入为壁纸源、视口尺寸、滚动偏移、主题、透明度模式和卡片矩形；输出直接写入当前 Canvas 帧，不调用 `setState`、`setData` 或 `canvasToTempFilePath`。

## 折射模型

玻璃中心仅叠加低透明冷白或冰蓝色，不对整块背景做强模糊。距离卡片边缘 6–12px 的区域执行折射：

- 沿边缘法线向内采样，位移在外缘最大、向中心平滑衰减。
- 采用约 1.01–1.03 倍局部放大，避免卡片中心像另一张贴图。
- 仅在亮边加入非常轻的青色和白色分离，不能形成彩虹描边。
- 圆角裁剪与页面现有卡片圆角一致。
- 文字区域不被采样进背景，防止出现重复文字或隐私内容残影。

“降低透明度”启用后提高中心填充不透明度和文字对比度，但保留边缘折射；它仍放在服务／我的设置，不新增大尺寸浮动控件。

## 数据流与滚动同步

### 页面滚动

工作区、任务、功能和个人资料使用页面滚动事件：

1. 页面加载完成后测量卡片的文档坐标。
2. `usePageScroll` 只更新滚动偏移 `ref`。
3. 通过 Canvas 自身的 `requestAnimationFrame` 合并高频事件，每帧最多绘制一次。
4. 仅绘制当前视口内的卡片。

### “我的”内部滚动

“我的”使用内部 `ScrollView`，由该滚动容器把 `scrollTop` 传给同一渲染器。渲染器不假设所有页面都触发 `usePageScroll`，避免“我的”再次出现卡死或折射位置不动。

### 静止状态

首屏完成测量后立即绘制一帧。滚动停止后保留最后一帧，不隐藏折射、不延迟 140ms 重新导出图片，也不运行永久动画循环。只有主题、布局、透明度模式或滚动位置变化时才请求下一帧。

## 生命周期

- `onShow`：恢复渲染并请求一帧。
- `onHide` / `onUnload`：取消待执行帧并释放页面持有的 Canvas 引用。
- 窗口变化：重新计算画布尺寸、像素比例和卡片矩形。
- 主题变化：重绘离屏壁纸，再请求可见帧。
- 内容异步变化：由页面在列表或卡片结构稳定后触发一次重新测量。
- 初始化失败：记录受控错误状态并切换到降级材质，不阻塞页面交互。

所有异步回调都检查当前页面实例是否仍有效，防止离开页面后晚到回调继续绘制。

## 性能预算

- 每页最多一个可见 Canvas 和一个离屏 Canvas。
- 设备像素比上限为 `1.5`。
- 每帧最多处理 8 个可见玻璃区域，其余区域使用降级边缘样式。
- 不在帧循环中调用 React 状态更新、节点查询、图片导出、文件写入或网络请求。
- 不保持永久 60fps 循环；事件驱动地请求帧。
- 连续滚动时若上一帧尚未完成，只保留最新滚动位置，不排队补画旧帧。
- 低性能判定以 Canvas 初始化失败、帧耗明显超出预算或内存压力为依据，降级后本页会话不反复尝试恢复。

目标是常见真机滚动与点击无明显阻塞；视觉精度必须让位于交互流畅度。

## 降级行为

当 Canvas 2D、离屏 Canvas、所需绘图能力不可用，或页面触发性能保护时：

- 使用干净的低透明冰蓝填充、单层细亮边和内侧暗线。
- 保留主题、文字对比度、按压反馈和所有业务交互。
- 不加载 `lens-light.png`、`lens-dark.png`，不显示重复圆弧或伪折射纹理。
- 不向用户弹出技术错误；开发环境可记录一次诊断信息。

## 页面接入

公共页面共用同一渲染组件和绘制核心，只分别声明本页需要折射的选择器与滚动来源。业务内页不挂载组件，也不继承公共页的 Canvas 样式。

旧的 `TextureRefraction` 固定贴图路径从公共页移除；相关 `lens-*.png` 可在确认没有其他调用后删除。已有 `NativeGlassMaterial` 的“Canvas 导出 PNG、滚动停止后刷新”路径不得接入新公共页。

## 测试

### 单元与组件测试

- 折射几何在边缘产生位移，中心区域保持稳定。
- 不同卡片坐标采样不同的壁纸区域。
- 滚动偏移会连续改变采样位置，不复用过期矩形。
- 同一帧只处理最多 8 个可见区域。
- 多次滚动事件在一帧内合并，并以最新位置绘制。
- 页面隐藏和卸载后取消帧，晚到回调不再绘制。
- 页面滚动与内部 `ScrollView` 两种数据源均能驱动同一渲染器。
- Canvas 初始化失败时启用干净降级材质且页面仍可点击。
- 登录页和业务内页不挂载动态折射组件。
- 公共页不再引用或渲染固定 `lens-*.png`。

### 构建验证

- 全量测试通过。
- `npm run build:weapp` 通过，微信开发者工具加载最新 `dist`。
- 构建产物不包含公共页对固定 lens 纹理的引用。
- WXSS 兼容检查通过，Canvas 层不拦截点击。

### 视觉验收

必须在微信开发者工具和至少一台真机检查五个公共页，不能以测试通过、构建成功或页面打开替代视觉验收：

- 同一背景光带穿过卡片时连续且只在边缘弯折。
- 不同卡片没有重复圆弧图案。
- 静止时折射常驻；连续滑动时跟手；停止时不闪现。
- “我的”内部滚动与其他页面表现一致，切换页面和退出登录不冻结。
- 文字、图标、视频封面、按钮和底部导航清晰可读且可点击。
- 深浅主题和“降低透明度”模式均可用。
- 登录页、入场动画和业务内页保持原状。

## 完成边界

只有在源代码、自动化测试、`dist` 构建、微信开发者工具五页滚动检查和真机检查全部通过后，才可称为“动态折射已修好”。本设计不授权上传体验版或发布新版本；上传需用户另行明确要求。
