# 批量工厂移动端四层工作台设计

## 目标

让微信小程序以公网批量工厂为唯一业务来源，同时针对手机屏幕重新组织信息层级。流程固定为：

`个人作品首页 -> 批次小说列表 -> 全局配置模板 -> 单本小说工作区`

UI 可以参考剪映的预览、素材轨道和底部操作栏，但不复制剪映业务。任何作品、小说、提示词、资产、任务状态和视频均必须来自服务端；前端不得用样例数据补足空结果。

## 页面与职责

### 1. 个人作品首页

- 数据：`GET /api/batch-factory/v11/batches`。
- 展示批次封面（有真实 `coverUrl` 才显示）、标题、小说数量、批次状态和最近更新时间。
- 主操作只有“新建批量”；导入小说在批次创建/批次页流程中完成。
- 空、加载、未授权、失败分别展示，不混为“暂无数据”。

### 2. 批次小说列表

- 数据：批次详情、`/status`、`/merge-status`、`/automation`。
- 展示当前批次的小说列表；每一行显示书名、真实书籍 ID、来源平台和服务端生产状态。
- 点击整行进入单本工作区；批量操作包括刷新、立即执行和定时执行，能力由 `capabilities` 决定。
- 页面顶部显示当前批次继承的配置模板摘要，并提供“统一配置”入口。

### 3. 全局配置模板

- 数据：`GET /api/batch-factory/v11/config-versions`，选择后通过公网已有配置/批次接口应用，不在小程序本地保存业务配置。
- 模板显示名称、版本和服务端返回的摘要；当前批次显示继承关系。
- 应用模板时明确作用范围为当前批次及其未覆盖的小说。
- 若服务端没有编辑能力，页面只读；不伪造保存成功。

### 4. 单本小说工作区

- 数据：批次详情、`/books/{bookId}/stages`、`/books/{bookId}/assets`、每个资产的 `/images`、批次 `/status`。
- 顶部显示书名、返回小说列表和读取状态。
- 预览区只使用真实视频 `mediaUrl`。没有 URL 时显示任务状态：未启动、排队中、生成中、失败、已完成但未返回媒体回执。
- “分镜”标签展示真实镜头/阶段；选中镜头后在详情抽屉展示服务端视频提示词。
- “素材”标签展示真实人物/场景资产；选中资产后展示图片回执、资产类型和服务端资产提示词。
- “任务”标签按书籍过滤服务端任务，显示 provider task、失败原因和重试入口。
- 底部操作栏提供重新读取、生成分镜、生成视频、合成；每个按钮由服务端 capability 和当前状态控制。

## 媒体读取边界

API 请求继续使用现有业务 Bearer 会话。图片和视频不把 token 拼到 URL，不写入日志或浏览器存储。相对媒体地址由服务层使用鉴权请求下载到小程序临时目录，再交给原生 `Image`/`Video` 组件；若公网媒体地址已允许小程序合法域名直读，则仍需验证播放和读回，不以 URL 存在代替可播放。

## 状态与错误

- `loading`：正在读取具体接口。
- `empty`：接口成功但没有记录。
- `unavailable`：能力或接口明确不可用。
- `error`：请求失败，保留重试按钮和服务端错误摘要。
- 生产状态按真实任务拆分：未启动、排队中、生成中、失败、完成、有 provider task、有 `mediaUrl`、可播放/读回。
- 不把 HTTP 200、提交成功或任务存在当作视频完成。

## 实现边界

- 复用现有批量工厂页面状态机（作品/批次/单本），不新建第二套批次流程。
- 扩展 `BatchFactoryBookWorkspace` 表达生产状态、资产图片和媒体回执。
- 小程序构建产物仍为 `dist/`，微信开发者工具只编译 `dist/`。
- 当前公网微信登录会话接口仍需后端提供有效路由和合法域名配置；在该前置条件完成前，只能标记为“真实公网登录待验收”，不能宣称小程序已上线可用。

## 验收标准

1. 单元测试证明 loader 请求批次、阶段、资产、资产图片和状态接口，并按 `bookId` 过滤任务。
2. 组件测试证明无图片/无视频回执时不渲染假媒体，且显示真实状态文案。
3. `npm test -- --run`、`npm run build:weapp` 和 `git diff --check` 通过。
4. 微信开发者工具以新构建的 `dist/` 编译，在有真实账号会话时验证：首页、批次列表、模板选择、单本提示词、图片读回和视频播放/失败状态。
