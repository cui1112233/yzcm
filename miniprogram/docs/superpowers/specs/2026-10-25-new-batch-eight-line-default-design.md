# 新建批量默认八行设计

## 目标

新建批量默认使用原文前 `8` 个非空逻辑行，并在用户每次进入“新建批量”时显示 `8`。已有小说继续展示服务端已保存的真实内容范围，不用新默认值覆盖历史数据。

## 根因

新建页的 React 初始状态、打开新建页时的重置逻辑，以及 `importBatchBooks` 在调用方未传值时的缺省值都写死为 `5`。用户在当前表单改成 `8` 只影响当次提交；下次进入页面又被重置回 `5`。

## 已确认行为

- 新建批量首次进入：`AI 内容范围` 显示 `8`。
- 用户退出后再次进入新建批量：重新显示默认 `8`，不沿用未提交草稿。
- 创建调用未显式提供 `contentRangeLines`：服务层使用 `8`。
- 创建调用显式提供其他合法值：尊重调用方值，不强制改成 `8`。
- 已有小说存在 `sourceMetadata.contentRangeLines`：读取并显示服务端值，例如历史 `5` 或已保存的 `8`。
- 已有小说缺少该元数据：继续采用旧数据兼容缺省 `5`，避免把未保存的历史范围误报为 `8`。
- `contentCaptureCharacters` 继续默认 `4000`，本次不改。

## 实现边界

- 将“新建批量默认内容范围”定义为独立常量，供页面初始值、重新打开重置和导入服务缺省共同使用。
- `readContentWindow` 的历史兼容缺省保持 `5`。
- 不修改服务端接口、元数据格式、保存回执校验、自动化启动顺序或既有批次数据。

## 测试与验收

- 单元测试先证明当前新建缺省仍为 `5`，再改为 `8`。
- 页面源码测试验证初始值和 `onCreate` 重置都引用八行默认值，不再出现新建流程的硬编码 `"5"`。
- 服务测试验证未传 `contentRangeLines` 时保存 `8`，显式传入时仍保留该值。
- 内容窗口测试验证空元数据仍读取为历史兼容 `5`，保存为 `8` 的元数据读取为 `8`。
- Taro 构建后在微信开发者工具进入“批量工厂 → 新建批量”，确认字段和摘要均显示前 `8` 个非空行。

## 非目标

- 不批量迁移历史小说。
- 不改变获取上限、自动化、提示词或生产设置。
- 不发布或上传新版本，除非后续收到明确指令。
