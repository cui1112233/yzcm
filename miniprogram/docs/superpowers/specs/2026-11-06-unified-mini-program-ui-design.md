# 全部小程序统一 UI 与布局设计规格

## 目标

统一剧本生成、私人定制漫画、批量工厂及其他功能页内部的视觉和交互基础，同时保留工作区首页、顶部品牌栏和外层液态玻璃工作台不变，并保留深色与浅色两个主题。

统一不是把所有页面做成同一张卡片，也不是改掉工作区外壳，而是让功能内部共享同一套组件语义、间距、圆角、按钮层级、输入方式、状态反馈和高级设置交互。业务差异只通过图标、文案和少量语义强调色表达。

## 当前问题

- `app.scss`、页面专属 SCSS 与 `comic.scss` 各自维护大量背景、文字、边框和强调色。
- 选择项普遍使用大卡片，标题、说明、当前状态和切换动作重复占用空间。
- 画幅、风格、模型、参考图等高级配置与主流程平铺，导致继续/生成动作下沉。
- 同一种动作在不同页面有不同按钮权重和命名，用户无法形成稳定预期。
- 深色和浅色存在，但部分页面用专属硬编码颜色覆盖共享 token，主题切换后的层级不对应。

## 设计原则

1. 双主题保留：深色与浅色共享布局和组件，只切换颜色 token。
2. 主流程优先：首屏只展示完成当前步骤所需的输入和选择。
3. 渐进披露：高级设置默认收起，点击后使用底部抽屉或半屏弹层承载。
4. 单一主动作：每个页面只保留一个明确的主按钮，次要动作降级为次按钮或文字入口。
5. 选择即反馈：选项使用紧凑单选行、胶囊或缩略图列表，选中状态通过描边、底色和勾选表达，不重复显示“当前/切换/已选”。
6. 微信约束优先：交互区域不小于 44px，兼容安全区、窄屏和 WXSS 限制，避免依赖不稳定的网页 CSS。
7. 外层玻璃保留：液态玻璃背景、动态壁纸和主题光晕作为统一页面壳保留；玻璃只负责环境层，不承担表单、选择和主操作的可读性。
8. 功能内部平面化：剧本生成、漫画生成等功能内容区使用实色表面、细边框和轻阴影，不使用玻璃、模糊或透明叠层。

## 统一页面骨架

```text
品牌顶栏
  返回 / 品牌 / 当前栏目

页面标题区
  标题 + 一句说明

步骤条（仅流程页）
  当前步骤、已完成步骤、禁用步骤

主内容区
  必填输入
  当前选择摘要
  必要的 1~2 个选项

高级设置入口
  更多设置 · 当前值摘要

底部固定操作栏
  次操作：返回 / 保存草稿
  主操作：继续 / 开始生成
```

## 组件行为

### 选择项

- 画幅使用紧凑三选一胶囊或单选组，默认显示当前值和一行说明。
- 风格使用横向缩略图列表，默认展示有限数量，“查看全部”进入半屏选择器。
- 项目与书目使用摘要行，点击后进入选择抽屉，不长期铺开全部项目。
- 参考图使用预览 + 更换/移除；上传、生成、查看详情通过操作菜单进入。

### 输入

- 文本、链接和提示词使用统一输入容器，标签、占位符、错误和帮助文案采用同一层级。
- 长文本区域保留明确最小高度，但不把结果预览、原始正文和编辑态混在同一张卡片。
- 选择器使用统一 `mp-picker-field` 外观，点击后调用原生 Picker 或项目内底部抽屉。

### 操作与反馈

- 主按钮统一使用 `mp-primary`，次按钮统一使用 `mp-secondary`。
- 状态统一为状态胶囊、进度条和错误行，不再用大面积颜色块表达状态。
- 异步操作进入 loading 后保持原按钮位置；错误提供就地重试，不改变页面骨架。
- 生成、删除、提交等不可逆或计费动作使用统一确认弹层。

### 高级设置

- 默认折叠，仅展示摘要，例如“更多设置 · 竖版 9:16 · 国漫风格”。
- 展开后使用底部抽屉/半屏弹层；确认后回写摘要，不在主页面堆叠所有选项。
- 抽屉内保留“取消”和“应用”语义，未应用的草稿不影响当前任务参数。

## 主题 token

`ui/tokens.ts` 作为唯一颜色来源，覆盖页面底色、卡片表面、抬升表面、主文字、次文字、分割线、边框、主强调、强调浅底、成功、警告、错误和信息色。页面专属 SCSS 不再直接写入同义硬编码颜色；需要业务强调时使用语义 token，不新建独立背景体系。

深色主题采用深海蓝底 + 分层蓝灰卡片表面；浅色主题采用冷灰蓝底 + 白色卡片表面。主强调色使用克制的蓝色，成功、警告、错误和信息色保持独立语义，不把所有状态都染成蓝色。两套主题的文字对比、按钮对比和状态颜色分别通过测试校验。

## 页面迁移顺序

1. 共享 token、`mp-theme`、按钮/输入/卡片/状态/抽屉基础样式。
2. 剧本生成、小说获取、批量工厂等功能内部工作流页面。
3. 私人定制漫画的设置、资产、确认、出图和结果页。
4. 其他功能页内部的输入、选项、结果和高级设置。

工作区首页、品牌顶栏、外层玻璃背景与动态壁纸不在本次改造范围内，只做 token 接入和兼容性保护。

迁移过程中保留现有业务逻辑、请求链路和状态机，只替换布局容器、展示组件和样式引用。现有液态玻璃背景层继续保留，但收敛为统一的深色/浅色参数，不允许页面再叠加独立的玻璃卡片体系。每组页面完成后进行窄屏溢出、深浅主题和交互状态检查。

## 验收标准

- 所有核心页面在深色和浅色下拥有相同的布局骨架和操作顺序。
- 画幅、风格、项目、书目、参考图和模型等选择不再以重复大卡片长期占据主内容区。
- 每个流程页首屏能看到当前步骤、当前摘要和唯一主操作。
- 高级设置可打开、取消、应用，并在主页面正确回显。
- 320/375/390/430px 宽度下无横向溢出，操作区满足触控尺寸。
- 现有功能测试、主题 token 测试和微信 WXSS 兼容性检查通过。
- 真实微信开发者工具中的深浅主题切换和关键流程视觉检查完成后，才能宣称视觉验收通过。
