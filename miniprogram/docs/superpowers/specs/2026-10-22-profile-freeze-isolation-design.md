# “我的”页真机冻结隔离诊断设计

## 目标

制作 `1.0.8` 体验版，在不改账号接口、会话语义和其他页面视觉的前提下，判断“我的”页冻结是否由液态玻璃合成层导致，并让真机失败时留下可见、可截图的阶段证据。

成功标准：

- 登录页底部显示 `v1.0.8`。
- 点击“我的”后，退出登录、重新读取和主导航始终可操作。
- 页面明确显示当前停在会话检查、请求发送、服务端响应或渲染完成中的哪一步。
- 请求无响应时在 15 秒内进入可重试失败态，不再永久保留初始加载画面。
- 不显示令牌、Cookie、账号密码或完整请求头。

## 已知证据与判断边界

- 真机已确认运行 `1.0.7`，但“我的”页的退出登录和全部导航均无响应。
- 公网 `https://yzcm.site/api/member/me` 的 DNS、TLS 和无会话响应正常；无会话请求约 0.13 秒返回 `401`，并携带会话失效响应头。
- 当前装饰覆盖层均声明不接收触摸；未发现一个明确的普通透明层拦截所有按钮。
- “我的”页仍启用全屏液态壁纸、固定自定义玻璃导航和实时背景模糊。当前证据只支持“真机渲染层过载”是首要假设，尚未证明它就是根因。

## 方案

### 1. 页面材质隔离

仅将 `pages/profile/index` 从液态玻璃页面名单中移除。该页不渲染 `LiquidGlassMaterial`、`LiquidNavigation`、逐卡折射边缘或任何 `backdrop-filter`，恢复项目已有的普通深色页面材质和微信原生 TabBar。

登录页、工作区、任务页、功能入口页和业务内页保持现状。此次不做全局材质回退，也不调整玻璃视觉参数。

### 2. 可见诊断阶段

“我的”页维护一个只用于界面展示的阶段枚举：

1. `session-check`：正在检查本机账号会话。
2. `request-started`：已向 `/api/member/me` 发起读取。
3. `response-received`：已收到 HTTP 结果，准备校验并渲染。
4. `rendered`：账号资料已渲染。
5. `failed`：请求失败、超时、会话失效或数据格式不完整。

阶段展示只包含客户端版本、阶段名称、耗时区间和安全错误分类。禁止展示业务令牌、Cookie、账号密码、完整响应体或完整请求头。

### 3. 数据流与超时

进入页面后，React 挂载兜底和原生 `useDidShow` 仍可触发读取，但由同一个请求锁去重：

`检查会话 -> 发起请求 -> 最长等待 15 秒 -> 收到结果并校验 -> 渲染资料`

若会话缺失或服务端明确返回会话失效，清理失效会话并进入登录页。网络失败、域名错误和超时留在当前页，显示可重试状态。迟到响应不得覆盖更新的请求或新的账号会话。

### 4. 交互与降级

- 加载状态同时提供“取消并返回登录”操作，避免用户只能等待。
- 失败状态提供“重新读取”和“返回登录”。
- 普通材质页直接使用微信原生 TabBar，不再依赖自定义固定玻璃导航完成切页。
- 即使资料请求失败，页面按钮与 TabBar 也必须保持可响应。

## 测试设计

自动化测试覆盖：

- `mp-profile-page` 不再被判定为液态玻璃页面。
- Profile 页面挂载和 `useDidShow` 同时触发时只发送一次请求。
- 阶段按会话检查、请求发送、响应、渲染顺序推进。
- 卡住的请求在 15 秒内进入失败态。
- `401` 会话失效进入登录页；网络错误保留安全错误分类与重试按钮。
- 登录页显示 `v1.0.8`。

构建验证包括完整 Vitest、TypeScript、`git diff --check`、生产微信构建以及 `dist` 内容核对。

## 真机验收

上传 `1.0.8` 后按以下顺序验收：

1. 在登录页确认底部版本为 `v1.0.8`。
2. 登录并点击“我的”。
3. 观察页面是否可交互以及最终诊断阶段。
4. 测试退出登录和三个其他主导航入口。
5. 若普通材质下恢复正常，确认根因位于液态玻璃合成路径，再单独设计低成本材质替代方案。
6. 若仍冻结，根据最后可见阶段进入真机 Console/Network 调试，不再继续猜测视觉层。

## 非目标

- 不修改公网账号、服务端身份或 API 协议。
- 不修改其他页面的液态玻璃效果。
- 不进行全局性能重构。
- 不把模拟器通过、构建成功或上传成功当作真机问题已经解决。
