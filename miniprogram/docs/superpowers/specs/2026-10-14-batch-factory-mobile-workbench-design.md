# 批量工厂小程序移动工作台设计

**状态：用户已确认视觉与信息架构，待用户审阅本文档后编写实施计划。**

## 目标

把批量工厂做成可执行的移动生产工作台，而不是静态展示页。它必须遵循网页端已经存在的对象层级和服务端事实源：用户先管理自己的批量工厂作品，进入一件作品后管理其小说，最后在当前小说内执行生产、合成和发布操作。

本轮设计只规定小程序 UI、路由状态、服务端投影和验收边界。不新增服务端能力，不猜测第三方平台字段，不把浏览器会话或密钥带入小程序。

## 已确认信息架构

```text
批量工厂
  -> 个人作品
       -> 新建批量
       -> 打开一个批量工厂作品
            -> 作品生产区
                 -> 小说列表
                 -> 统一配置 / 自动生产 / 批量操作
                 -> 当前小说工作台
                      -> 原文与生产内容
                      -> 人物与场景
                      -> 单书配置
                      -> 分镜与视频
                      -> 合成与发布
```

### 领域映射

- 一个“个人作品”对应一个服务端 `Batch`，不是单本小说，也不是 VIDEO。
- 一个作品中的 `books[]` 是小说列表；小说列表只属于当前作品。
- 作品生产区的外层单位是一部小说。书内分镜、VIDEO 候选、合成任务和发布任务不得提升为外层作品行。
- Batch/Book 不存在单一可信总状态。界面汇总必须保留阶段运行、生产任务、合成任务和发布回读的边界。

## 视觉系统

选择“浅色封面作品架 + 当前书工作台”。

- 背景：冷白和浅灰绿色，避免大面积纯色面板。
- 文字：深墨绿；交互主色为翡翠绿；蓝色表示运行，暖橙表示待处理，红色表示失败。
- 圆角：常规组件最大 8px；不使用渐变、发光球、营销式大卡片或嵌套卡片。
- 图标：沿用小程序 `AppIcon` 中的真实位图资源；按钮采用图标或图标加明确命令文本。
- 封面：优先用服务端实际封面、首帧或合成封面。无真实媒体时使用统一文字封面，不能随机生成或伪造素材图。
- 所有长标题必须截断或换行，不让文字挤压状态、按钮或安全区。

## 页面设计

### 1. 个人作品首页

这是批量工厂的默认首页，读取当前账号可见的 Batch 列表。

- 顶部显示“我的作品”、搜索和“新建批量”。
- 主区域是两列封面作品架，每张作品只显示：真实封面或文字封面、作品标题、小说数量、服务端更新时间、简短聚合状态。
- 筛选为全部、进行中、待处理、已完成；无法可靠聚合时归入“状态未返回”，不能猜测完成。
- 点击作品后读取该 Batch 详情，再进入作品生产区。
- 空状态只显示“还没有批量作品”和“新建批量”；加载和读取失败状态必须独立呈现，失败可重试。

### 2. 新建批量

从个人作品首页打开原生底部抽屉或独立子页，不能覆盖作品库的导航语义。

字段和顺序：

1. 作品名称。
2. 服务端书城目录选择；不再预填或硬编码平台 ID、平台名称。
3. 每书城书单输入和已添加分组，可编辑或删除分组。
4. 内容范围与原文截取范围。
5. 创建方式：仅创建作品、立即执行、定时执行。
6. 自动化预设、执行模式、并发数；只有服务端已返回可用预设时才允许立即或定时执行。

“仅创建作品”只完成获取原文、创建 Intake/Batch 和进入新作品，不启动 AI、视频、合成或发布。定时执行必须在服务端保存未来北京时间；小程序退出后任务仍由服务端管理。

### 3. 作品生产区

打开作品后，顶部显示返回个人作品、作品标题、小说总数和真实聚合进度。工具栏提供：小说列表、统一配置、自动生产和批量操作。

移动端采用“顶部小说轨道 + 当前书工作台”：

- 小说轨道横向滚动，仅显示书名、状态色和短状态；不显示一组堆叠制作卡。
- 用户切换小说后，工作台固定显示当前书，切换不影响其它书的数据或任务。
- 作品汇总仍可查看执行中、待处理和完成的数量；批量动作必须先明确作用于当前书、勾选书或全部书。
- 小说列表是当前作品的子视图，展示序号、书名、Book ID、书城、风格、男女频、内容来源和真实状态；支持全选/单选和进入当前书。

### 4. 当前书工作台

当前书按业务阶段组织为四个紧凑区域，所有操作都带 `batchId` 和 `bookId`：

1. **原文与生产内容**：原文、有效内容范围、开头候选、变更影响。原文保存后，受影响资产/分镜/视频必须提示“需更新”，不能静默覆盖。
2. **人物与场景**：资产描述、提示词、图片候选和主图。显示单项生成、失败和重试；没有服务端能力时显示能力原因。
3. **分镜与视频**：按分镜展示提示词、候选版本、实际时长、ProviderTaskId、运行状态、失败原因和单条重试。一本书内一个失败 VIDEO 不得伪装成整书失败。
4. **合成与发布**：合成进度、受保护成片预览、当前主视频选择，以及发布目标、文本/视频逐文件回执、提交记录和平台读回。

中文界面不出现 `Director`、`VIDEO` 或内部 revision 字段；这些仅可留在代码和服务端兼容层。

## 服务端边界

现有小程序可以继续复用的调用包括：Batch 列表/详情、手动 Intake、Intake 创建 Batch、原文抓取、自动化预设、立即/定时启动、暂停/继续/重试/取消、单书导演、单书视频阶段提交和单书合成提交。

实施前必须补齐或确认下列读取/写入契约，不能在 UI 中用样例代替：

| 移动区块 | 所需服务端事实 | 当前处理原则 |
| --- | --- | --- |
| 书城选择 | 当前账号可用书城目录和平台 ID | 没有可信目录时禁止提交，不允许默认平台 |
| 作品架 | Batch 标题、小说数量、更新时间、封面或真实缺失状态 | 只显示实际返回字段 |
| 小说轨道/列表 | Book 元数据、阶段摘要和聚合状态 | 未返回时显示“状态未返回” |
| 设置/资产/提示词 | 当前书的设置、资产、图片、提示词和变更影响 | 缺接口显示不可用原因，不伪造编辑成功 |
| 视频 | ProductionJob/ProductionTask、候选媒体、ProviderTaskId、错误 | 按视频任务状态展示和重试 |
| 合成 | MergeJob 进度、成片媒体、错误 | 成片成功不等于发布成功 |
| 发布 | 目标组织、能力、上传回执、审计和平台读回 | 没有真实读回不得显示“已发布” |

密钥、模型凭据、121 会话 Cookie、组织授权和平台上传凭据继续只留在服务端；小程序只提交非敏感 ID 与用户选择。

## 状态与错误处理

每个读取或写入区域都必须有加载、真实内容、真实空结果、不可用、失败、重试六种明确状态。

- `queued`、`running`、`succeeded`、`failed`、`cancelled` 必须保留阶段或任务上下文。
- 历史失败被后续成功 attempt 覆盖后，不能继续显示为当前失败。
- 自动化任务、单书阶段、VIDEO、合成和发布分别显示，不能压缩为一个“生产中”或“完成”。
- 能力接口明确拒绝时，操作禁用并显示服务端原因；能力键缺失不能默认可用。
- 所有刷新只更新服务端返回的事实，不把本地点击状态写作生产成功。

## 路由与实现边界

- 保留小程序四个原生 Tab；批量工厂是二级页面，使用现有 `BrandHeader` 返回上一级。
- 页面内部状态建议是 `works -> create -> project -> novel-list -> book`，浏览器式 URL 不是小程序业务事实。
- 不将网页 React、Ant Design Modal、Cookie 会话、localStorage 或静态示例数据迁入 Taro。
- 不修改当前脏工作树中的无关页面、环境文件、图标或用户变更。

## 验收

1. 以真实登录账号打开批量工厂，首页只展示当前账号可见的 Batch 作品；空、加载、失败和重试均可见。
2. 从首页新建批量，书城来自服务端目录；仅创建时确认没有自动启动生产。
3. 打开新作品后，小说列表只显示该作品的 Books；返回个人作品后仍能见到作品。
4. 在任一书中操作内容、资产、分镜、视频、合成和发布时，确认请求都带当前 `batchId`、`bookId`，且不影响其它书。
5. 对一个失败 VIDEO 只重试该任务；确认其它视频和书的成功结果不丢失。
6. 没有发布能力、目标、上传回执或平台读回时，界面明确阻塞且不显示发布成功。
7. 运行相关单元测试、`npm run build:weapp`，再在微信开发者工具重新编译 `dist/`；以已绑定账号验证上述读写、失败和回读边界。

构建成功、按钮可点或 HTTP 200 不构成真实生产或发布验收。
