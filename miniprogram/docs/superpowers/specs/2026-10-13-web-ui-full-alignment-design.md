# 网页 UI 全量对标设计

## 目标

以 `http://127.0.0.1:5176/` 的移动工作区为视觉规格，重构微信小程序的全部已实现页面。保留小程序的真实会话、服务端读取、提交操作和微信宿主导航；只改变信息组织、布局、图标资产和交互表面。

## 视觉系统

- 容器：深色实底、细分隔线、紧凑单列工作区；不用装饰性大面积渐变或网页中的假微信胶囊。
- 顶部：Logo 左侧 14px，栏目名置于 Logo 下方；使用真实微信状态栏和系统胶囊；详情页在左侧保留真实返回操作。
- 间距：页面水平 14px，主区块 16px，行项目 12px，卡片圆角 8px 到 12px。
- 图标：将网页同名 Lucide 描边图标导出为本地静态小程序资产。禁止继续用 Unicode 符号承担功能图标。箭头、刷新、返回等操作图标同样用资产而非文本字符。
- 状态：加载、空、错误和重试保持真实服务端语义，不改写为静态示例内容。

## 页面范围

1. 一级导航：工作区、任务、功能、我的；补齐微信 TabBar 的四个图标并让标签、选中态和底部安全区对齐网页。
2. 工作区：将主视觉降为网页的紧凑工作台标题区，快捷入口改为带图标的功能行，最近记录和本机最近入口统一为网页卡片层级。
3. 任务：使用网页的标题行、图标刷新、筛选条、来源标识、进度与状态卡片；不丢失多来源汇总结果。
4. 功能：从分组长列表改为网页的连续工具卡，六个模块使用网页同名图标与色调，当前模块状态保留。
5. 我的与详情：个人资料、服务、开发者工具和移动端设置与网页同组；按服务端角色展示，菜单图标与网页一致。
6. 工作区详情：剧本、小说获取、小说面板、水货生产、Agent 和批量工厂统一为紧凑的标题区、分段控件、真实状态卡和图标操作区；不更改各自的数据和请求边界。
7. 绑定页：使用登录卡与账户图标，保留密码不落地和绑定成功后回工作区的现有行为。

## 实现边界

- 采用本地静态图标资源，避免运行时网络图标请求和字体兼容性风险。
- 不引入新的业务 API、浏览器存储或模拟统计数据。
- 不替换微信系统的状态栏、更多按钮和关闭能力。
- 深层页面若网页没有同名移动组件，沿用其卡片、标题、操作条和图标规则，不伪造网页尚未提供的业务功能。

## 验收

- 源码和 `dist/` 均无 Unicode 功能图标、伪微信胶囊或固定高度导致的内容裁切。
- 各一级页和六个工作区存在相应图标资产、加载/空/错误/重试状态及真实操作入口。
- 自动测试、TypeScript 检查和微信构建通过。
- 在微信开发者工具手动编译后，至少验收工作区、任务、功能、我的、一个详情页和绑定页；网页与小程序可因系统状态栏不同而有垂直偏移，但层级、图标语义和交互入口一致。
