# 小程序车祸坠落登录动画设计

## 目标

把用户提供的 5.042 秒竖版动画作为唯一动作母版，保留骑车、碰撞和角色坠落的连续性。角色坠落时落到蓝色插画登录框上沿，画面稳定后无跳变地切换为可输入的真实登录界面。

源素材：`264421a9b1a22e77e953bebdc25d2a41_raw.mp4`，720 x 1280，H.264 + AAC，约 16.7MB。

## 已确认方案

采用“原视频直放 + 撞击遮挡转场 + 透明成品图末帧 + 原生登录框接管”。不再对白底视频逐帧抠图，不在播放中的微信原生 `Video` 组件上叠加输入框，也不把视频拆成逐帧大图。

独立样片使用用户提供的透明合成图 `codex-clipboard-5ab00a25-6ed7-4451-8d28-8444da0f66f4.png` 作为干净末帧。原视频保持完整画面直到女角色最终落下；落地瞬间用短促白光、星点和轻微画面震动遮挡姿势切换，随后透明合成图从轻微压缩状态回弹到稳定位置。这样不需要从视频中提取白色角色，彻底避免灰褐水彩底和白色毛发混在一起造成的脏边。

实施分为两个独立验收阶段：

1. **独立动画样片**：只制作一段可单独播放的成片，完整展示骑车、车祸、坠落、砸到登录框和回弹。此阶段不修改小程序源码、不替换现有登录动画，也不上传体验版。
2. **小程序集成**：用户确认样片的动作、落点、尺寸和质感后，才接入 `LoginScene`，实现视频末帧到原生登录框的无缝切换。

原因：

- 原视频直放能完整保留骑车、车祸和坠落的连续动作，不因抠图破坏白色毛发边缘。
- 撞击遮挡把原片的地面落点转换为透明成品图中的登录框落点，视觉上形成一次主动的华丽变身，而不是暴露硬切。
- 真实登录框只在动画结束后出现，规避微信原生视频组件层级和输入控件遮挡问题。
- 逐帧大图既保留原视频的脏白底，又会扩大包体、纹理内存和跨 JS 桥更新压力，因此明确不采用。
- 当前 `dist` 已约 2.3MB，原始视频不能进入小程序主包。

## 动画时间轴

最终时间以逐帧审片取得的碰撞帧和落地帧为准，不凭估算硬切。目标节奏如下：

1. `0.00s - 碰撞前`：保留原视频骑车运动，不叠加登录控件。
2. `碰撞帧 - 4.32s`：原视频保持完整画面，不抠图、不叠登录框。
3. `4.32s - 4.46s`：女角色最终落下时出现一次中心白光、少量星点和 2-3px 等效画面震动；白光峰值遮住原片地面与成品图登录框之间的姿势差。
4. `4.40s - 4.62s`：透明成品图由 `96%` 纵向压缩、约 `102%` 整体缩放回弹至最终尺寸，模拟角色和框体一起承受撞击。
5. `4.62s - 5.45s`：透明成品图稳定停留，保留足够审看片段；背景为干净纯白，不出现视频白底纹理。
6. `样片结束`：独立预览直接结束。后续接入小程序时，再在 120-180ms 内交叉淡化为原生登录页。

## 画面与布局

- 动画保持竖屏 `9:16`，使用 `aspectFill` 覆盖登录舞台，安全区域以 390 x 844 逻辑画布校准。
- 视频中的白色背景与登录页背景统一处理，避免视频边框或色温差暴露切换。
- 登录框和落定角色直接使用用户新提供的透明成品图，不再使用 `box.png` 与视频人物进行动态抠像合成。
- 透明成品图按宽度优先适配 540 x 960 画布，四周保留至少 10px 安全边距；角色、零件和登录框作为一个整体回弹，避免相对错位。
- 原生登录页接管后，继续使用当前眨眼、摇尾巴、钥匙扣摆动和密码错误哭泣状态。

## 媒体交付

- 原片前段保持不变，落地转场后延长干净末帧；移除音轨并编码为微信真机兼容的 H.264 MP4。
- 目标输出保持视觉清晰，首选 540 x 960、24fps；编码结果以真机流畅度为准，不以固定码率为唯一标准。
- 视频存放到已配置的 HTTPS 媒体域名，不进入主包。资源必须支持正确的 `Content-Type: video/mp4`、Range 请求和实际播放推进。
- 主包仅保留一张压缩后的首帧或末帧 PNG 作为海报及失败兜底。
- 若媒体域名未通过微信视频合法域名验证，动画不得阻塞登录；直接显示原生登录页并记录安全错误状态。

## 组件边界

### `LoginIntroVideo`

只负责加载和播放入场视频，并上报 `ready`、`playing`、`ended`、`error`、`skip`。不保存账号，不处理登录请求。

### `LoginScene`

继续拥有账号、密码、记住密码、自动登录、二步验证及角色状态。新增 `intro` 阶段，在视频完成或失败后进入现有 `ready` 阶段。

### 媒体配置

视频 URL、版本和兜底海报集中配置，避免散落在组件中。版本变更时通过资源版本号破除缓存。

## 状态流

```text
loading -> ready-to-play -> playing -> settling -> native-ready
   |             |            |
   +-------------+------------+-> fallback-native-ready
```

- `loading`：显示本地海报，不显示可输入控件。
- `ready-to-play`：视频已具备播放条件，立即静音播放一次。
- `playing`：允许“跳过动画”，不响应表单输入。
- `settling`：视频末帧与原生登录框短暂交叉淡化。
- `native-ready`：卸载视频，只保留真实登录界面。
- `fallback-native-ready`：加载超时、解码失败、域名失败、应用切后台或减少动态效果时直接进入登录。

## 交互与容错

- 视频静音、自动播放一次，不循环。
- 用户触摸“跳过动画”后立即卸载视频并显示原生登录页。
- 页面切后台时暂停；返回前台后若已超过允许等待时间，直接进入原生登录页，不从中间突兀续播。
- 视频加载设短超时。失败不得白屏、不得阻止输入、不得把 `onError` 当作播放完成证据。
- 开启减少动态效果时不播放视频，直接显示最终登录界面。
- 已有自动登录会话时缩短或跳过动画，避免动画阻塞自动登录。

## 验收标准

### 样片验收门

- 先交付可独立播放的 MP4 样片和关键帧预览。
- 用户明确确认“可以写入小程序”之前，不改现有登录页动画实现。
- 若样片需要调整，只迭代合成时间轴和视觉位置，不让未确认版本进入小程序构建。

### 动作

- 骑车、车祸和坠落完全来自原视频，不出现重新绘制导致的动作跳变。
- 白光峰值完整遮住原片地面落点到透明成品图登录框落点的切换；逐帧审查不得出现脏边或双影。
- 落定后角色、零件与登录框作为整体回弹，不发生相对穿模。
- 视频末帧切换到原生登录框时，关键元素位移不超过 2 个逻辑像素。

### 功能

- 动画期间表单不可误触；动画结束、跳过或失败后表单立即可用。
- 密码显隐、记住密码、自动登录、二步验证和错误哭泣保持现有行为。
- 重进页面时状态可预测，不出现重复叠播或音频。

### 真机与媒体

- iOS 和 Android 微信真机均能首帧显示、开始播放并推进到结尾。
- 精确视频 URL 返回 MP4，支持 Range，并在真机网络面板中无域名错误。
- 断网、慢网、解码失败和切后台均能回退到可用登录页。
- 构建后核对正式 AppID、`dist` 路径、主包大小、版本号和体验版真机动画，不以模拟器或构建成功代替验收。

## 不在本次范围

- 不重画视频中的角色、车辆或车祸动作。
- 不对白底视频做逐帧抠像，不制作雪碧图或逐帧大图动画。
- 不改变登录认证协议和账号存储方式。
- 不把动画扩展到登录后的业务页面。
- 不自动上传或覆盖线上媒体，部署动作需使用明确的目标路径并完成读回验证。
- 独立样片阶段不修改小程序登录页代码、不重建体验版。
